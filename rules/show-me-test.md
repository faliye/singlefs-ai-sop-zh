# 准入铁律：Show me test

> **Make every submitted patch review-worthy.**
>
> 让每一份提交都值得被 review。

## 判据是测试

**patch 收不收，由自动化验证说了算。** 门禁过就是过，不过就是不过。

## 没有测试的 patch 一律不收

**改了 `crates/*/src/` 就得带测试。** 没有例外，「这个太简单了」「下个 patch 补上」都不算。只改文档和脚本除外。

由 `scripts/show-me-test.sh` 强制（`gate.sh` 把它当一个阶段跑）。

## 新增的测试必须先证明它会红

**每个「验证」都得能失败。** 做法是：**先把被测代码改坏，看着测试变红，再改回来。**
证明不了会红的测试，等于没写。

脚本只看得出有没有测试，查不了这一步：**在 commit message 里写明你是怎么确认它会红的**——
改坏了哪一行，看到哪个断言失败。写不出来就是没做。

有变异 harness 的仓要再进一步：把「改坏哪里 → 哪条断言红」做成**存进仓里的变异清单**，
交给门禁反复复跑。commit message 里的叙述是没有 harness 时的退路，不是首选。

**设计论证同样照办**：对抗轮打中的每一条，先在模型里做成一个**必须报非 0** 的世界，再改规则。

## 踩过的坑要做成会失败的检查，不要做成提醒句

立的时机照 `sop-first.md`「边界」一节：先记欠账、按批立，正在反复发生的当场立。

踩到新坑，第一反应该是「这条怎么做成门禁里会红的一项」，不是「这条写进哪个文档」：
做成一个当场拒绝执行的检查，不写成「注意别在 X 的时候做 Y」这种提醒句。

### 但要先问这个坑在哪一层：装置里，还是口径上

**判据不是「这个坑做没做成会红的检查」，是「这个坑在哪一层」**：

| 坑在哪 | 检查立在哪 |
|---|---|
| 一段代码的行为里 | 那段代码旁边就够 |
| **建模口径上**（同一个量该怎么算、边界算不算、单位是什么） | **立在装置之间**：两套装置算同一个量，就要有一条检查逼它们落到同一个数；对不上判红 |

**快速判据**：换一套装置、从头把同一件事再做一遍，还会不会再踩一次？会，它就在口径层，检查要跨装置立。

**跨装置的检查要钉住「这个名字指的是哪个量」**：两个量就登记两个名字，各钉各的值
（`code-discipline.md`「一个语义概念全仓一个名字」）。

## 最终判据由项目定

单元测试这类检查只是快速反馈，**不是准入标准**。
准入标准跟被测对象绑在一起：要起什么环境、跑什么负载、注入什么故障，都由项目自己定、自己测、自己验，
装置和它的门禁阶段都放在项目里，共享门禁不带。
未实现清单里一直列着「最终判据」。写这个键之前，先把准入标准写进项目自己的 kb：起什么环境、跑什么负载、注入什么故障。
阶段把这几样都做到了，才在头部写 `# gate-covers: 最终判据`；只做到一部分的不写。
阶段覆盖了清单里别的哪一项，也一样写 `# gate-covers: <那一项>`。这一轮跑了且通过，`gate.sh` 才把那一项从未实现清单里换成「由哪个阶段覆盖」。

## 门禁不许假装通过

没实现的门禁阶段要**明说没实现**，不许悄悄跳过。

**项目本地阶段这一轮无对象可判，退出码写 77**：`gate.sh` 记「本次未跑」，不记通过，也不算覆盖。
`exit 0` 的跳过在汇总里与「判过了」分不出来，这一半靠写阶段的人。
共享阶段同规矩：无对象可判的退 77（`Show me test` 与命名纪律退 3），`gate.sh` 用认得 77 的起法起它们。

**阶段只跑了一部分，跳过的那一部分逐项报进汇总**：缺工具跳过的用例、本语言没实现的样本、没配样本的本地阶段，
用 `lib.sh` 的 `report_not_run` 报（不 source `lib.sh` 的阶段往 `$GATE_NOT_RUN_FILE` 追加一行，这个变量不在时不写：单跑与喂样本时它不在），
`gate.sh` 收进汇总的「本次未跑」；只在阶段输出里 warn 一句不算报了。报过的那一次不记成「上次成功」（`rules/preflight-discipline.md`），
报过的本地阶段也不算覆盖了 `# gate-covers:` 那一项。

**跑批脚本不许把单轮的失败吞掉**（`|| true` 那种），输出路径也不许跨轮复用。
判据是「这份输出能不能证明是这一轮产生的」：跑之前删掉旧输出，跑完认一个本轮才会出现的完成标记。

**扫到 0 项也不是通过。**
扫一批对象的检查，成功那句里要报出**检查了多少项**；`gate-lint.sh` 判这一条：判的是脚本里最后一句成功句，
它要带一个在脚本里数出来的量（累加过的变量、数组长度、`wc -l` / `grep -c` 的结果）；确实不扫对象的脚本单独写一行注释
`# gate-lint:nocount <理由>`，理由至少 8 个字。

**报了「查了多少」还不够，「没查的是哪些」也要逐个列出，而且清单要现算。**
**跳过清单要与被扫集合出自同一份数据、现算**；成功那句同时报「跑了 N 个；没跑 M 个：逐个列名」。
这一条还没做成检查：`gate-lint` 现在不看报了数的脚本有没有同时列出跳过项，靠写阶段的人自己守。

# 一条改动不同步铺满全仓时，排除的每一份都要登记

一个规范、一次操作、一次改动只铺了一部分文件时，**没铺到的要逐条登记进一张排除表**，
一行一条、`#` 后面写为什么不铺。**没有排除表就意味着全仓都要改。**

判据不是「改起来麻烦」，是「改了这句话就成假的，或者改了某道闸就失效」：
别家项目的术语与原文引文、某道检查自己的输入、工具自己的模式表、说这次改动本身的那句话——
这几类改了会出错，登记；其余一律改。

排除表**指向不存在的路径判红**。表本身要能被一条命令读。

**成功那句里报的数，本身也要有东西钉住。** `gate-lint` 不管这一条，靠写阶段的人。

**项目本地阶段与共享阶段同规矩**，一样受 `gate-lint` 与 `shell-lint` 管：`gate.sh` 把 `.claude/gate.d/` 一并交给这两个 lint。

**射程只到 `.claude/gate.d/`。** 项目别处的脚本（研究脚本、hook）不在这两个 lint 的射程里。
项目有这类目录，就在 `.claude/gate.d/` 里接一个本地阶段，把它们交给这两个 lint，两个都要接：
调用时分别设 `GATE_LINT_DIR`、`SHELL_LINT_DIR` 指到目标目录。

# 门禁能证明什么，不能证明什么

> **Gate proves evidence requirements, not semantic correctness.**
>
> 门禁证明的是证据要求被满足，不是代码语义正确。

## 能通过全部门禁、却仍然是错的

| 情形 | 门禁够不着的地方 |
|---|---|
| 测试测的是实现，不是契约 | 门禁只数有没有测试，不判测得对不对 |
| 声明本身写错了 | 声明与实测一致就判「符合」，而声明是错的。**除非有对照组**，否则什么也没证明 |
| 不变量本身就是错的 | 检查会老老实实判一条错规矩，而且全绿 |
| 覆盖的不是出问题的那条路径 | 覆盖率不是正确性 |
| 正文引的数与它自己的产物对不上 | 复跑的**区间**断言只钉住结论落在哪一档，不钉正文里的那个数：区间有多宽，正文就能漂多远 |
| 两套装置对同一个量算出不同的数 | 断言与变异只在**一套装置内部**生效，跨装置没有任何东西在对 |
| 设计本身就错了 | 门禁根本够不着这一层 |

## 推论

1. **门禁绿不等于可以不看代码。** 人去看**测试测的是不是对的东西**。

2. **语义对不对，写在 `kb/decisions.md` 和 `kb/invariants.md` 里，不在门禁里。**
   门禁只保证这两样**写下来了、实现了、而且和代码同步**。
   它们本身写得对不对，靠人。

3. **门禁是下限，不是上限**（`rules/sop-first.md`）。

4. **没实现的阶段要一直列出来。** `gate.sh` 每次都打印这份清单。
   项目阶段声明覆盖了某一项（`# gate-covers:`），也要这一轮跑过且通过，那一项才从清单里换下来。

5. **交回的清单能被机器核全，不等于判对了。**
   子 agent 逐项判的活（回扫、复核），能做成检查的是「每一项都有判定、判定是认得的那几种、理由里引了那一项的原话」，
   它拦得住「抽样够了」「整组放行」，拦不住判错。核全之后还要在**全部判定种类**里抽查复判，抽中判错的那一段重做、再抽。

## 不按来源分类，只看证据

这个项目**不按来源分类**，也不给哪一类单开规矩。
只分两种：**带证据的提交，和不带的。**
