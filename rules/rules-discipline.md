# 规则文件铁律

**管的是**：`rules/*.md`、项目本地的 `.claude/rules/*.md`，也就是**照着执行的规矩**。

设计文档照 `design-doc-discipline.md` 写，给模型检索的知识照 `kb-discipline.md` 写。
agent 定义与 skill 正文同规矩，检查各自另立。

## 1. 正文只写四样

| 写 | 不写 |
|---|---|
| 怎么做：步骤、次序、判据、阈值 | 为什么这么定：论证、取舍、推导 |
| 做什么、不做什么：射程与例外 | 这条怎么来的：实测、日期、谁定的、踩过的坑 |
| 推荐怎么做：拿不准时的默认选项 | 当时是什么样：旧值、旧做法、改动经过 |
| 什么规则在哪里：指到别的规则、脚本或 kb | 门禁判别力的经过与数 |

## 2. 判据留下，论证搬走

照它能判出该不该做、做到哪算完的是**判据**，留在正文；解释那条判据为什么成立的是**论证**，删掉。

- 「删掉这句，读的人少知道什么？说不上来就删」是判据。
- 「啰嗦的代价不是占地方，是让有用的话被埋掉」是论证。

同一段里两样都有时，留判据那一句，其余整段删掉，不留摘要。

## 3. 搬出来的东西直接删掉

不另立落点，也不去别处补一份；正文不留「（原为 <旧值>）」「此前如何」这类痕迹。
共享规则的历史只进 `CHANGELOG.md`，一版一节。删掉的论证以后要用，重新论证一次。

## 4. 指向历史的链接要带劝阻句

正文要指 `CHANGELOG.md`、`records/` 或 kb 里那份材料时，**同一行**写上劝阻句：

> 历史与依据：`CHANGELOG.md` 的 0.0.53 那一节。**除非要查来历，别读它。**

劝阻句写成「别读」或「不要读」，一字不许省。

## 5. 规则文件不留历史节

`CLAUDE.md` 与 `rules/*.md` 连文末的「## 历史版本」都不留。

## 6. 立一条新规则之前，先问它能不能变成会失败的检查

判据与写法在 `sop-first.md` 的「边界」一节。

## 7. 正文不许用位置指代，也不许自称

射程是 `rules/*.md`、`CLAUDE.md`、`agents/*.md`、`skills/*/SKILL.md`。
判据与改法同 `kb-discipline.md` 第 1 条「每条事实自足」，两处不同：

- 自称只判指文档结构的那几个词：「本节」「本章节」「本表」「本文档」「本条」。「本实验」「这条决策」这类领域对象词不判。
- 时间指代（「本轮」「这一轮」）不判。

别处的事实链到它所在的文件。

带 `<!-- doc-lint:rule-definition -->` 牌的文件，反引号与「」里的举例不判，正文照判。

## 8. 正文不写某一个使用者的东西

正文里不许出现使用它的项目的名字、它的路径、它的文件名，也不许拿它的决策号、实验号当示例。
举例写成不指名的形态：`.claude/gate.d/` 这类接法路径写得，它下面带序号的某一个具体文件名写不得。

## 门禁管哪一半

| 条 | 谁判 |
|---|---|
| 第 1、3、4、5 条能落成字面的那一半 | `scripts/rules-lint.sh`：记录小节、论证小节、带日期的行、解释性段落与半句、词法说明、没带劝阻句的历史链接 |
| 第 7 条 | `scripts/doc-lint.sh` |
| 第 8 条 | `scripts/rules-lint.sh`，只认两种：使用它的项目的名字、门禁目录里带序号的具体文件名（`gate.d/<数字>-`）；决策号、实验号与别的路径它认不出；只判本包自己的规则 |
| 第 2 条的分界、劝阻句底下的链接指得对不对 | review |

`rules-lint.sh` 扫本包的 `rules/`，也扫项目的 `.claude/rules/`（没有这个目录时扫 `.claude/agents/`）、项目 `CLAUDE.md`、agent 定义与 skill 正文，后一样由 `gate.sh` 的阶段「规则纪律（项目本地）」起。
还没回扫完的文件逐个登记进项目根的 `.claude/rules-lint-exclude`，改完一个删一行，排除只缩不涨。
判据按本包的语言取，没实现的那几样它显式报未实现。
