# 编码纪律：machine-first 的实施细则

写代码时照着做。审老规矩的流程在 `machine-first.md`；总纲是 `engineering-philosophy.md` 的「AI 友好 ≠ 不可读」：
放宽的只有为了让人脑装得下而做的压缩，把含义写明白这件事一点都不放宽。

**不让过去的最佳实践替我们做决定。** 流行做法逐条审过的结果在「逐条审过的流行做法」。
没列进来的准则，用之前先走一遍 `machine-first.md` 的流程，默认是存疑，不是照做。

管的是这个项目里我们自己写的全部代码：产品代码、测试、实验代码、脚本。
门禁查到哪一步，见「门禁管哪一半」。

## 名字：光看名字，就说得出它是什么、做什么

**判据：不看注释、不看调用点、不看实现，光看这个名字，说不说得出它是什么、做什么、不做什么。**
说不出就改名。起不出这样的名字，先想清楚这段代码要做什么。

管的是**我们自己声明的每一个名字**：变量、参数、函数、方法、类型、字段、枚举成员、常量、
模块、文件、泛型参数、生命周期、闭包参数、循环变量、测试函数、宏。
外部定下的名字不归我们管：实现 `Display` 就得叫 `fmt`。

| 规矩 | 细则 |
|---|---|
| **长度不设限** | 没有「名字要短」这一条 |
| **不用缩写** | `cnt`、`idx`、`buf`、`tmp` 一律写全。例外只有登记过的领域缩写，见「缩写登记表」 |
| **不用单字母** | 循环变量、闭包参数、泛型参数、生命周期、错误绑定都算：`i` → `stripe_index`，`T` → `Key`，`'a` → `'journal`，`Err(e)` → `Err(error)` |
| **前置条件和作用范围写进名字** | `write_node` 什么都没说；`append_verified_node_to_journal` 说了三件事：追加不覆盖、入参验过、落在日志区 |
| **单位写清** | 类型表达得了就交给类型（`LogicalAddress`、`Duration`）；表达不了就写进名字：`offset_in_blocks`，不是 `offset` |
| **布尔写成判断句** | 说清哪一边为真：`is_checksum_verified`，不是 `flag`、`status`、`ok` |
| **测试名写场景和预期** | `crash_between_data_write_and_commit_keeps_previous_generation`，不是 `test_commit`、`it_works` |
| **一个语义概念全仓一个名字** | 单位是语义概念，不是词：同一个概念不许这里叫 `generation`、那里叫 `epoch`；两个概念哪怕底层含义相近（盘上记的代号、事务生命周期里的代号），也不许共用一个名字，各自带上角色：`committed_generation`、`transaction_generation` |
| **名字自己站得住，不靠模块路径补全** | 写 `block::BlockAddress`，不写 `block::Address`。类型名因此连成一套人工命名空间（`BlockAddress`、`JournalAddress`、`LogicalAddress`……），照这样写 |
| **换了含义就换名字** | 同名遮蔽只在含义不变时用；原始数据变成验过的、字节数变成块数，就起新名字 |

### 缩写不许用，判据是有没有一处权威定义

**判据是「有没有一处权威定义」，不是「大家看不看得懂」。**
Rust 的关键字和基本类型名（`mut`、`fn`、`str`、`u64`）不算缩写，语言规范就是它们那一处定义；
项目自己的领域缩写（`lba`、`crc`）要登记了才能用。

### 缩写登记表

项目根的 `.claude/abbreviations`，一行一条，`#` 后面写全称和含义：

```text
lba  # logical block address：逻辑块地址，文件系统给块编的号
crc  # cyclic redundancy check：循环冗余校验
```

登记表就是这个缩写唯一的权威定义，别处照它用，不另写一份。
**单字母不许登记。**

**项目自己的编号**（kb 里登记的实验号、决策号这类）当名字的一段用时，按「字母加数字」这一整类登记：

```text
e<数字>  # 实验编号，登记在 .claude/kb/experiments.md
```

登记之后 `e57_field_authority` 里的 `e57` 就不算单字母。编号在名字里同样要带着简称
（`kb-discipline.md` 第 5 条）：写 `e57_field_authority`，不写光秃秃的 `e57`。

### 语义放在哪：注释 < 名字 < 类型

同一件事的三种写法，从差到好：

```rust
// 一、语义在注释里 —— 最差
// dim0: 民族  dim1: 性别  dim2: 年龄段
pop[i][j][k]

// 二、语义在名字里
number_of_china_people[han][woman][teenager_18_to_24]

// 三、语义在类型里 —— 最好，写错维度直接编译不过
number_of_china_people[Ethnicity::Han][Gender::Woman][AgeBand::Teenager18To24]
```

**类型能表达的交给类型，类型表达不了的写进名字，都别写进注释。**

## 分支：穷举写全，不写通配臂

```rust
enum Medium {
    Rotational,
    SolidState,
    Zoned { zone_size_in_bytes: u32 },
}

fn node_size_in_bytes(medium: &Medium) -> u32 {
    match medium {                                  // 没有 `_ =>` 通配臂：新增一种 Medium 不补这里就编译不过
        Medium::Rotational                   => 64 * 1024,
        Medium::SolidState                   => 16 * 1024,
        Medium::Zoned { zone_size_in_bytes } => (*zone_size_in_bytes).min(256 * 1024),
    }
}
```

**判据不是「分支多不多」，是「漏了一种情形谁先发现」**：要让编译器先发现，不是生产环境。

- **封闭集合的枚举，`match` 不写 `_ =>`。** 我们自己的枚举默认是封闭集合：有几种情形由我们说了算。
- **语义上允许未知值的**（盘上读到的、协议里收到的、以后还会加新值的编码），把「未知」做成一个显式成员
  （`Unrecognized(raw_code)`），`match` 照样穷举，也不写通配臂。
- **真正开放的只有两种**：外部的枚举（别的库的、标了 `#[non_exhaustive]` 的），以及我们对外承诺、
  要给以后留演进余地的公开 API（见「什么时候不套用」）。确实需要通配臂时，
  在那一处写 `#[allow(clippy::wildcard_enum_match_arm, reason = "…")]`。
- **工作区内部用的枚举不标 `#[non_exhaustive]`。**
- **封闭的集合（有几种情形由我们说了算）用 `enum` 加穷举 `match`，不用 trait 对象。**
  两种情形之间的交互（状态转移、两两比较）可以写成对元组的穷举 `match`。开放的集合（插件、测试替身）照旧用 trait。
- **只有一个实现的 trait 不抽。** 至少有两个真实现（对拍用的模型也算一个）才抽 trait；
  不为「以后好换」而抽。
- **穷举 `match` 的臂数不算复杂度。** 要限的是彼此独立的条件。

## 类型：让非法状态写不出来

```rust
#[derive(Clone, Copy, PartialEq, Eq)] pub struct LogicalAddress(pub u64);
#[derive(Clone, Copy, PartialEq, Eq)] pub struct PhysicalAddress(pub u64);
fn read_block(address: PhysicalAddress) -> Block;   // read_block(LogicalAddress(value)) 编译不过

struct RawNode(Vec<u8>);        // 刚从盘上读出来，未验证
struct VerifiedNode(Vec<u8>);   // 校验和已比对通过
impl RawNode {
    fn verify(self, expected_checksum: Checksum) -> Result<VerifiedNode, CorruptBlock> { /* ... */ }
}
fn walk(node: &VerifiedNode) { /* ... */ }   // 想跳过验证就构造不出入参
```

- 同一种底层类型承载不同含义（逻辑地址、物理地址、代号；字节数、块数），各给一个 newtype。
- 「验没验过」「落没落盘」这类状态做成类型，不做成布尔字段。**边界上验一次**，换成带着证明的类型，
  往里就信类型，不在每一层重复检查。
- **布尔参数换成枚举**：`write(node, true)` 写成 `write(node, Durability::Synced)`。
- **有不变量的字段私有**，只能从检查过的构造函数进来；
  没有不变量的字段直接公开，不写样板 getter / setter。
- **带不变量的类型不实现 `Default`。**
- **构造我们自己的结构体时，每个字段都写出来**，不用 `..Default::default()`。
  必填的字段不交给 builder 在运行期查，写成构造函数参数；只有真可选的才进 builder。
- **会丢值的数值转换不用 `as`**：会丢值的方向用 `try_from` 并处理失败，不会丢值的方向用 `from`。

## 错误：能恢复的写进类型，破坏不变量的就断言

- **能恢复的失败**（I/O 错、盘上数据损坏、资源不够）**走 `Result`**。错误枚举的成员**按调用方要做的决定分**，
  不按底层原因逐个展开：比如上层要分流的只有「没找到」「数据损坏」「空间不够」「其它 I/O 错」几种，
  底层几十种系统错误挂在「其它 I/O 错」那个成员里当 source 带着。
- **判据是调用方有没有因此失去该有的决定。** 库代码的公开边界不用 `anyhow`、`Box<dyn Error>` 这种统一错误类型；
  也不把每一种底层失败都在每一层重新展开成一个成员。测试和命令行工具可以用统一错误类型。
- **不变量被破坏是 bug，用断言**，不带着坏状态往下跑、更不往盘上写。
- **不写 `unwrap()`，写 `expect`**，消息写清它依赖哪条不变量：
  `expect("journal 头在 open() 里验过；这里是 None 说明验证被跳过了")`。

## 函数与嵌套：按「能单独验证」切，按路径数限

**函数的长度按「一件能单独验证的事」定，不按屏幕高度定。** 一件事写三百行可以；
两件事挤在二十行里要拆开。

**嵌套层数不设限，限的是路径数。** 不带提前出口的循环嵌套几乎不增加路径（`break`、`continue`、`?` 每个都会添一条），
条件嵌套按指数增加（12 层独立 `if/else` 是 2¹² 条）。
层数随意，只要两条都满足：路径数说得出、而且有限；
每一层的迭代对象有名字、有类型，不是 `a[i][j][k][l]`。

**路径数只量控制流，不是验证难度的全部。** 路径数超了就拆；没超不等于好验。循环还要另外写清三件事：
迭代次数的上界、跨轮携带的状态和它的不变量（写成断言）、每一个提前出口。
**「只有一条路径」不能拿来给一个难验的算法辩护。**

- **参数不按个数限。** 每个参数有名字、有类型就行；只有几个参数本身构成一个带不变量的概念时，
  才收成一个类型，不为了让签名变短而凑结构体。
- **结果放进返回类型**，不用 `&mut` 输出参数传回。
- **副作用挤到边上，核心写成纯函数**，带 I/O 的外壳越薄越好。一个函数既查又改，名字要把两件事都说出来。
- **提前返回随便用。**

## 注释、断言、常量、重复

- **注释只写「为什么这样」**，不写「这在做什么」。
  约束写进类型、名字或断言，不写进注释。
- **文档注释写类型表达不了的契约**：会返回哪些错、什么时候 panic、`unsafe` 要调用方保证什么。
  复述名字的文档注释删掉。
- **每个 `unsafe` 块上面写 `// SAFETY:`**，说清为什么安全。
- **不变量写成断言**，不只写进文档。
- **魔法数字写成命名常量**：一个数只许有一处定义，名字或类型里带上单位。
- **重复要生成，不许手抄。** 宏和 `build.rs` 是生成的正路，只做生成、不藏逻辑，
  生成出来的东西要有测试盯着。
- **用不到的代码删掉**，注释掉的代码也删。
  编译器报的 `never used` 当错误处理（`command-safety.md`：警告是免费的信号）。
- **`TODO` 写清缺什么、为什么现在不做。** 欠着的检查记进项目 kb 的欠账表，代码里指过去。

## 逐条审过的流行做法

每一条都照 `machine-first.md` 的流程审过。**处置**只有六种：废弃、放宽、改写、留下、交给工具、降为建议。

### 整体理念

| 流行做法 | 出处 | 处置 | 我们的写法 |
|---|---|---|---|
| 代码读的次数比写的多，要为读的人优化 | 《Clean Code》等 | **改写** | 为机器验证和信息量优化；人的注意力留给测试对不对、不变量对不对、依据成不成立、取舍要不要（`engineering-philosophy.md`） |
| 别写聪明的代码 | 通行说法 | **留下** | 照做 |
| KISS，保持简单 | 通行说法 | **改写** | 简单指控制流路径少、要验的状态少、每条路径都写明，不指行数少 |
| YAGNI，用不到的别写 | 极限编程 | **留下** | 用不到的代码不写 |
| 最小惊讶原则 | 通行说法 | **留下** | 名字和类型带够信息，让模型猜对行为 |
| 约定优于配置 | Rails 等框架 | **废弃** | 不靠隐式的默认行为：要的值都写出来 |
| 关注点分离、高内聚低耦合 | 通行说法 | **留下** | 边界清楚、契约明确，每一块能单独验证 |
| 文件、模块不要太长 | 通行说法 | **放宽** | 模块按契约切，不按行数切 |

### 命名

| 流行做法 | 出处 | 处置 | 我们的写法 |
|---|---|---|---|
| 名字要短，离声明越近越短 | Go 代码评审意见、Linux 内核编码风格 | **废弃** | 长度不设限，见「名字」 |
| 循环计数叫 `i`，临时变量叫 `tmp` | Linux 内核编码风格 | **废弃** | 按它是什么命名：`stripe_index`、`unflushed_block` |
| 泛型参数用 `T`、`U`，生命周期用 `'a` | Rust 惯例 | **废弃** | 按角色命名：`Key`、`Value`、`'journal` |
| 大家都认得的缩写可以用 | 通行说法 | **废弃** | 写全；领域缩写登记之后才能用 |
| 名字要念得出来 | 《Clean Code》 | **留下** | 要的是不歧义、搜得到 |
| 名字要搜得到 | 《Clean Code》 | **留下**，而且更硬 | 一个语义概念一个名字，全仓搜一次就全 |
| 匈牙利命名法、`m_` 前缀、接口名加 `I` | C / C++ / C# 旧惯例 | **废弃**，它想做的事交给类型 | 含义不同就是不同的 newtype；类型表达不了的单位写进名字 |
| 不用 `Manager`、`Helper`、`Data`、`Info` 这类噪音词 | 《Clean Code》等 | **留下** | 删掉它名字没少说什么，就不用它 |
| 模块名别在类型名里重复（`block::Address`） | clippy 的 `module_name_repetitions`、Go 的包命名惯例 | **废弃** | 名字自己站得住：写 `BlockAddress` |
| 取值方法不加 `get_` 前缀 | Rust API 指南 C-GETTER | **留下** | 照 C-GETTER 写 |
| 转换方法按 `as_`、`to_`、`into_` 命名 | Rust API 指南 C-CONV | **留下** | `as_` 借用到借用、约定几乎无开销；`to_` 约定有开销，多半产出新值，也有 `to_str` 这种借用出借用的；`into_` 消费所有权。以 C-CONV 那张表为准，实现要兑现名字所说的那一类开销 |
| 布尔名以 `is_`、`has_` 开头 | 通行说法 | **留下** | 说清哪一边为真 |
| 类型用名词、方法用动词 | 《Clean Code》 | **留下** | 名词说它是什么，动词说它做什么 |
| Rust 的大小写约定（`snake_case`、`CamelCase`） | Rust 惯例，rustc 默认警告 | **留下** | 照约定写 |
| 同名遮蔽（`let text = text.trim()`）是惯用法 | Rust 惯例 | **改写** | 含义不变可以遮蔽；换了含义就换名字。含义无关的遮蔽由 clippy 拦 |
| 测试函数叫 `test_<被测函数>` | 通行惯例 | **废弃** | 写场景和预期结果 |

### 函数

| 流行做法 | 出处 | 处置 | 我们的写法 |
|---|---|---|---|
| 函数要短：一两屏，最好不到 20 行 | 《Clean Code》、Linux 内核编码风格 | **留下** | 按「一件能单独验证的事」切，不按行数 |
| 只做一件事 | 《Clean Code》 | **留下** | 一个函数一个能单独验证的契约 |
| 每个函数只有一个抽象层次 | 《Clean Code》 | **放宽** | 不强求；要紧的是契约清楚、路径数有限 |
| 从上往下读（下沉规则） | 《Clean Code》 | **废弃** | 不要求函数按调用顺序从上往下排 |
| 参数最多三个 | 《Clean Code》 | **放宽** | 每个参数有名字、有类型就行；成概念才收成类型 |
| 不用标志参数 | 《Clean Code》 | **留下** | 换成枚举 |
| 不用输出参数 | 《Clean Code》 | **留下** | 结果放进返回类型 |
| 函数没有副作用；函数式核心、命令式外壳 | 《Clean Code》、Gary Bernhardt | **留下** | 核心写成纯函数；I/O 挤到外壳，外壳靠项目自己的装置验 |
| 查询与修改分开 | Bertrand Meyer（CQS） | **留下** | 既查又改的函数，名字把两件事都说出来 |
| 单一出口 | 结构化程序设计 | **废弃** | 提前返回随便用 |
| 嵌套不超过三层 | Linux 内核编码风格 | **放宽** | 层数不限，限的是控制流路径数；循环的状态另外验 |
| 圈复杂度不超过某个数 | McCabe，各类静态分析工具 | **改写** | 穷举 `match` 的臂数不算；限的是彼此独立的条件 |

### 类型、数据与封装

| 流行做法 | 出处 | 处置 | 我们的写法 |
|---|---|---|---|
| 用值对象代替基本类型 | 《重构》（基本类型偏执） | **留下**，而且更硬 | 含义不同就是不同的类型 |
| 让非法状态写不出来 | Yaron Minsky | **留下** | 见「类型」 |
| 解析，而不是校验 | Alexis King | **留下** | 边界上验一次，换成带证明的类型，往里信类型 |
| 字段私有，配上 getter / setter | Java 系的封装惯例 | **改写** | 有不变量的私有，没有的直接公开 |
| 默认不可变 | Rust 惯例、函数式编程 | **留下** | 照做 |
| 不用全局可变状态；不用单例 | 通行说法、《设计模式》的反面教材 | **留下** | 不用 |
| 能 derive `Default` 就 derive | Rust 惯例 | **改写** | 带不变量的类型不实现 `Default` |
| 结构体更新语法 `..Default::default()` | Rust 惯例 | **我们自己的结构体上废弃** | 每个字段都写出来 |
| 字段多就上 builder | Rust API 指南 C-BUILDER | **改写** | 必填的写成构造函数参数；只有真可选的才进 builder |
| 数值转换用 `as` | C 系惯例 | **会丢值的方向废弃** | 用 `try_from` 并处理失败，由 clippy 拦 |
| 别用 typedef 给结构体换个名字 | Linux 内核编码风格 | **废弃** | newtype 照用：包的是含义，不是藏结构 |
| 魔法数字要起名 | 通行说法 | **留下** | 一个数只许有一处定义，名字或类型带单位 |

### 分支与抽象

| 流行做法 | 出处 | 处置 | 我们的写法 |
|---|---|---|---|
| 用多态替换条件分支 | 《重构》 | **封闭集合上废弃** | `enum` 加穷举 `match`，见「分支」 |
| 开闭原则 | SOLID | **封闭集合上废弃** | 加一种情形，让编译器逼着把每一处旧代码过一遍 |
| 单一职责 | SOLID | **留下** | 一块只有一个能单独验证的契约 |
| 里氏替换 | SOLID | **留下** | trait 的契约对每个实现都成立：契约测试对每个实现都跑（同 `test-discipline.md` 的「阳性对照必须对**每一条**被测的臂都跑」） |
| 接口隔离 | SOLID | **留下** | trait 往小里切 |
| 依赖倒置：依赖抽象，不依赖具体 | SOLID | **改写** | 至少两个真实现才抽 trait，对拍用的模型算一个 |
| 迪米特法则：只和直接的朋友说话 | Northeastern 大学 Demeter 项目 | **放宽** | 模块内部随便链；跨模块不许穿过别人的内部 |
| 设计模式：工厂、策略、访问者 | 《设计模式》 | **改写** | 策略、访问者在封闭集合上写成 `match`；不为模式多加一层 |
| DRY，避免重复 | 《程序员修炼之道》 | **放宽** | 重复要生成，不许手抄 |
| 三次重复之后再抽象 | 《重构》（Don Roberts） | **留下** | 重复先交给生成器，不抽成吃掉穷尽性检查的通用路径 |
| `default:` / `_ =>` 兜底更稳 | 防御式编程 | **封闭集合上废弃** | 漏掉的情形交给编译器抓；允许未知值的，把「未知」做成显式成员 |

### 错误处理

| 流行做法 | 出处 | 处置 | 我们的写法 |
|---|---|---|---|
| 快速失败 | 《程序员修炼之道》 | **留下** | 不变量被破坏就断言，不往盘上写坏状态 |
| 库代码不 panic，一律返回 `Result` | Rust 惯例 | **改写** | 能恢复的走 `Result`；不变量被破坏是 bug，用断言 |
| 用 `anyhow`、`Box<dyn Error>` 统一错误类型 | Rust 生态惯例 | **库代码的公开边界上废弃** | 成员按调用方要做的决定分，底层原因当 source 带着 |
| 确定不会失败时用 `unwrap()` | Rust 惯例 | **废弃** | 用 `expect`，消息写清依赖哪条不变量 |
| 防御式编程：处处检查参数 | 通行说法 | **改写** | 边界上查一次，换成带证明的类型，往里不重复查 |
| 错误码还是异常 | 各语言之争 | **改写** | 失败写进返回类型 |

### 注释与文档

| 流行做法 | 出处 | 处置 | 我们的写法 |
|---|---|---|---|
| 多写注释 | 早期惯例 | **改写** | 注释只写为什么 |
| 注释是失败，好代码不需要注释 | 《Clean Code》 | **改写** | 「是什么」交给名字和类型；「为什么这样」照写 |
| 每个公开项都写文档注释 | rustc 的 `missing_docs` | **改写** | 复述名字的删掉；只写类型表达不了的契约 |
| `unsafe` 块写 `// SAFETY:` | Rust 惯例 | **留下，由 clippy 拦** | 每个 `unsafe` 块都写 |
| 注释掉的代码留着以后用 | 通行做法 | **废弃** | 删掉 |
| 在注释里记改动历史和作者 | 旧惯例 | **废弃** | 历史进 git 和 CHANGELOG（`design-doc-discipline.md`） |
| `TODO` 注释 | 通行做法 | **改写** | 写清缺什么、为什么现在不做；欠着的检查记进 kb |

### 格式

| 流行做法 | 出处 | 处置 | 我们的写法 |
|---|---|---|---|
| 每行不超过 80 列 | Linux 内核编码风格、PEP 8 等 | **交给工具** | `rustfmt` 的默认值说了算；名字长了就换行，不为行宽缩名字 |
| 8 格缩进，逼人少嵌套 | Linux 内核编码风格 | **废弃** | 层数不限，见「函数与嵌套」 |
| 竖向留白、相关的挨着放 | 《Clean Code》 | **交给工具** | 不手调 |

### 测试代码

| 流行做法 | 出处 | 处置 | 我们的写法 |
|---|---|---|---|
| 一个测试只写一个断言 | 《Clean Code》 | **废弃** | 一个测试一个场景；断言可以多条，每条的消息写清期望什么 |
| 覆盖率达到某个比例 | 通行做法 | **改写** | 拿路径数和变异清单说话（`test-discipline.md`） |
| 依赖一律 mock | 通行做法 | **改写** | 优先用对拍的模型和真实实现 |
| 测试金字塔：单测最多 | Mike Cohn | **改写** | 单测是快速反馈；准入靠项目定的最终判据（`show-me-test.md`） |
| 测试代码也要 DRY | 通行做法 | **放宽** | 每个测试自己读得出场景；搭建可以抽成辅助函数，断言不藏进去 |
| 不稳定的测试多跑几次就过 | 通行做法 | **废弃** | 不稳定就如实说不稳定，不许重跑到绿（`test-discipline.md`） |
| 先写测试 | Kent Beck（TDD） | **留下** | 先看着它红（`show-me-test.md`） |

## 什么时候不套用

**这些细则对「删得掉的东西」随便用，对「删不掉的东西」要另说。**
写进对外承诺的东西（磁盘格式、协议、公开 API），判据单独定，不能拿一句「显式更安全」推过去。

## 门禁管哪一半

| 细则 | 谁查 |
|---|---|
| 单字母名、常见缩写 | `scripts/naming-lint.sh`（门禁阶段「命名纪律」）：扫项目里每个 `.rs`，只看我们声明的名字 |
| 封闭集合的枚举不写 `_ =>` | clippy `wildcard_enum_match_arm`；声明开放的，在那一处 allow 并写 reason |
| `#[allow]` 要写 `reason = "…"` | clippy `allow_attributes_without_reason` |
| 会丢值的 `as` 转换 | clippy `cast_possible_truncation`、`cast_sign_loss`、`cast_possible_wrap` |
| `unsafe` 块要有 `// SAFETY:` | clippy `undocumented_unsafe_blocks` |
| 含义无关的同名遮蔽 | clippy `shadow_unrelated` |
| 警告按错误处理 | clippy `-D warnings` |
| 名字说没说清、一个概念是不是一个名字、函数是不是只做一件事、注释写的是不是为什么、错误成员是不是按调用方的决定分的、循环的状态有没有写清、`..Default::default()` | review |
| shell 脚本里的名字 | **还没做成检查**，`gate.sh` 把它列在未实现的阶段里。⚠️ 这条纪律对 shell 一样有效，但 `scripts/` 里的现有脚本没有回扫过，别拿它们当范例 |

clippy 那几条由 `scripts/check.sh` 带着跑，也就是门禁的「构建与单测」阶段；项目根没有 `Cargo.toml` 时这一阶段不跑。

`naming-lint.sh` 的缩写词表只列最常见的那些，**词表外的缩写照样违规**，只是门禁看不见。
它认不出的形态（跨行的模式、宏展开出来的名字）不判，交给 review，认不出不等于通过。
trait 实现里的方法名、关联类型，以及 `extern` 块里的声明，名字是外部定的，不查。

项目侧两份配置，一行一条，`#` 后面写理由，理由不许省：

| 文件 | 管什么 |
|---|---|
| `.claude/abbreviations` | 登记过的领域缩写，格式见「缩写登记表」 |
| `.claude/naming-lint-exclude` | 不扫的目录或单个 `.rs` 文件，写明为什么排除；指向不存在的路径、或者一个 `.rs` 都没排到，都判红。回扫旧代码时把还没改完的文件逐个列进来，改完一个删一行：排除只缩不涨，新文件照查 |

别的外部定名（外部格式的字段名这类），在那一行写 `// naming-lint:external <为什么这个名字不归我们定>`，
只豁免这一行，理由同样不许省。
