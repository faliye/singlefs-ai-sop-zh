# 编码纪律：machine-first 的实施细则

`machine-first.md` 讲为什么要重审老规矩、怎么审；这一篇是审完的结果，写代码时照着做。
总纲是 `engineering-philosophy.md` 的「AI 友好 ≠ 不可读」：放宽的只有为了让人脑装得下而做的压缩，
把含义写明白这件事一点都不放宽。

**原则只有一条：不让过去的最佳实践替我们做决定。**
流行的做法按出处成批审过一遍，结果在「逐条审过的流行做法」一节；前面几节是审完之后的写法。
没列进来的准则，用之前先走一遍 `machine-first.md` 的流程，默认是存疑，不是照做。

管的是这个项目里我们自己写的全部代码：产品代码、测试、实验代码、脚本。
门禁查到哪一步，见文末「门禁管哪一半」。

## 名字：光看名字，就说得出它是什么、做什么

**判据：不看注释、不看调用点、不看实现，光看这个名字，说不说得出它是什么、做什么、不做什么。**
说不出就改名。起不出这样的名字，多半是这段代码要做的事本身还没想清楚。

`fn f(a: u64, b: u64)` 和 `fn commit_transaction(generation: Generation, root: LogicalAddress)`
差的是一整层语义，模型读了实现也补不回来。

管的是**我们自己声明的每一个名字**：变量、参数、函数、方法、类型、字段、枚举成员、常量、
模块、文件、泛型参数、生命周期、闭包参数、循环变量、测试函数、宏。
外部定下的名字不归我们管：实现 `Display` 就得叫 `fmt`。

| 规矩 | 细则 |
|---|---|
| **长度不设限** | 没有「名字要短」这一条。多十个字符换一层语义，对机器永远划算 |
| **不用缩写** | `cnt`、`idx`、`buf`、`tmp` 一律写全。例外只有登记过的领域缩写，见「缩写登记表」 |
| **不用单字母** | 循环变量、闭包参数、泛型参数、生命周期、错误绑定都算：`i` → `stripe_index`，`T` → `Key`，`'a` → `'journal`，`Err(e)` → `Err(error)` |
| **前置条件和作用范围写进名字** | `write_node` 什么都没说；`append_verified_node_to_journal` 说了三件事：追加不覆盖、入参验过、落在日志区 |
| **单位写清** | 类型表达得了就交给类型（`LogicalAddress`、`Duration`）；表达不了就写进名字：`offset_in_blocks`，不是 `offset` |
| **布尔写成判断句** | 说清哪一边为真：`is_checksum_verified`，不是 `flag`、`status`、`ok` |
| **测试名写场景和预期** | `crash_between_data_write_and_commit_keeps_previous_generation`，不是 `test_commit`、`it_works` |
| **一个语义概念全仓一个名字** | 单位是语义概念，不是词：同一个概念不许这里叫 `generation`、那里叫 `epoch`；两个概念哪怕底层含义相近（盘上记的代号、事务生命周期里的代号），也不许共用一个名字，各自带上角色：`committed_generation`、`transaction_generation` |
| **名字自己站得住，不靠模块路径补全** | 写 `block::BlockAddress`，不写 `block::Address`：`use` 进来之后，调用点只剩 `Address`，模型看不到路径。这是**有意让名字带上命名空间的信息**，代价是类型名连成一套人工命名空间（`BlockAddress`、`JournalAddress`、`LogicalAddress`……），我们认这个代价；理由是检索结果和调用点上路径不在场，不是「名字越长越好」 |
| **换了含义就换名字** | 同名遮蔽只在含义不变时用；原始数据变成验过的、字节数变成块数，就起新名字 |

### 为什么缩写是纯亏

省下几个字符，丢掉的是语义，而模型补不回来——更糟的是它会瞎补。
`cnt` 在一处指块数、另一处指重试次数，检索到其中一处的模型不会说「我看不懂」，
它会按最常见的那个意思往下推。文件系统里的 `ext` 可以是 extent，也可以是 extension；
`gen` 可以是 generation，也可以是 generator。

**判据是「有没有一处权威定义」，不是「大家看不看得懂」。**
所以 Rust 的关键字和基本类型名（`mut`、`fn`、`str`、`u64`）不算缩写，语言规范就是它们那一处定义；
项目自己的领域缩写（`lba`、`crc`）要登记了才能用。

### 缩写登记表

项目根的 `.claude/abbreviations`，一行一条，`#` 后面写全称和含义：

```text
lba  # logical block address：逻辑块地址，文件系统给块编的号
crc  # cyclic redundancy check：循环冗余校验
```

登记表就是这个缩写唯一的权威定义，别处照它用，不另写一份。
**单字母不许登记**：一个字母没有唯一的含义。

**项目自己的编号**（kb 里登记的实验 E57、决策 D22 这类）当名字的一段用时，按「字母加数字」这一整类登记：

```text
e<数字>  # 实验编号，登记在 .claude/kb/experiments.md
```

登记之后 `e57_field_authority` 里的 `e57` 就不算单字母。编号在名字里同样要带着简称
（`kb-discipline.md` 第 5 条）：写 `e57_field_authority`，不写光秃秃的 `e57`。

### 语义放在哪：注释 < 名字 < 类型

同一件事的三种写法，从差到好：

```rust
// 一、语义在注释里 —— 最差
// dim0: 民族  dim1: 性别  dim2: 年龄段
pop[i][j][k]

// 二、语义在名字里 —— 以往被嫌啰嗦，机器很喜欢
number_of_china_people[han][woman][teenager_18_to_24]

// 三、语义在类型里 —— 最好，写错维度直接编译不过
number_of_china_people[Ethnicity::Han][Gender::Woman][AgeBand::Teenager18To24]
```

第一种是为了让人脑装得下而做的压缩：名字缩到最短，语义挪进注释。
在行宽和屏幕都有限的年代这么写是合理的，但注释会和代码脱节，名字不会——名字就是代码。
第二种每一维都自己说明自己，**不看上下文就能判断这次访问对不对**。
第三种把信息从「能读」推到「能检」，维度写反了编译不过。

**类型能表达的交给类型，类型表达不了的写进名字，都别写进注释。越往后越难与实现脱节。**

## 分支：穷举写全，不写通配臂

```rust
// ✗ 通用路径：新增一种情形时，编译器什么也不说
fn node_size_in_bytes(device: &Device) -> u32 {
    if device.is_rotational { 64 * 1024 } else { 16 * 1024 }
}
```

```rust
// ✓ 穷举分支：新增 Zoned 之后不补这里就编译不过
enum Medium {
    Rotational,
    SolidState,
    Zoned { zone_size_in_bytes: u32 },
}

fn node_size_in_bytes(medium: &Medium) -> u32 {
    match medium {                                  // 关键在于**没有** `_ =>` 通配臂
        Medium::Rotational                   => 64 * 1024,
        Medium::SolidState                   => 16 * 1024,
        Medium::Zoned { zone_size_in_bytes } => (*zone_size_in_bytes).min(256 * 1024),
    }
}
```

**关键就是那条没写的 `_ =>`。** 加上通配臂，代码看着更短更「通用」，
可它正好把编译器的穷尽性检查关掉了：以后新增一种情形，程序会安静地走进通配臂，
行为错了却没人报警。**判据不是「分支多不多」，是「漏了一种情形谁先发现」**：
编译器，还是生产环境。

- **封闭集合的枚举，`match` 不写 `_ =>`。** 我们自己的枚举默认是封闭集合：有几种情形由我们说了算。
- **语义上允许未知值的**（盘上读到的、协议里收到的、以后还会加新值的编码），把「未知」做成一个显式成员
  （`Unrecognized(raw_code)`），`match` 照样穷举。这时通配臂同样有害：以后新加一个已知成员，
  `_ =>` 会把它安静地送进「未知」那一臂，协议演进时最容易出的正是这个错。
- **真正开放的只有两种**：外部的枚举（别的库的、标了 `#[non_exhaustive]` 的），以及我们对外承诺、
  要给以后留演进余地的公开 API（见「什么时候不套用」）。确实需要通配臂时，
  在那一处写 `#[allow(clippy::wildcard_enum_match_arm, reason = "…")]`。
- **工作区内部用的枚举不标 `#[non_exhaustive]`**：它逼着工作区里别的 crate 在每个 `match` 上写通配臂，
  等于把穷尽性检查整个关掉。
- **封闭的集合（有几种情形由我们说了算）用 `enum` 加穷举 `match`，不用 trait 对象。**
  枚举把所有情形摆在一处，路径数数得出来；两种情形之间的交互（状态转移、两两比较）
  也能写成对元组的穷举 `match`，漏一种组合就编译不过。trait 的默认方法却相当于通配臂：
  新加一个实现，没覆写的方法安静地沿用默认行为。开放的集合（插件、测试替身）照旧用 trait。
- **只有一个实现的 trait 不抽。** 至少有两个真实现（对拍用的模型也算一个）才抽 trait；
  只为了「以后好换」而抽的那一层，是一个没人验的开放集合。
- **穷举 `match` 的臂数不算复杂度。** 编译器替你数着；要限的是彼此独立的条件，它们让路径按指数涨。

## 类型：让非法状态写不出来

```rust
// ✗ 同一种底层类型承载多种含义：混用编译通过，运行期才错
fn read_block(address: u64) -> Block;
fn free_extent(start: u64, length_in_blocks: u64);
// 调用点把逻辑地址传成物理地址，编译器无话可说
```

```rust
// ✓ newtype：混用编译不过
#[derive(Clone, Copy, PartialEq, Eq)] pub struct LogicalAddress(pub u64);
#[derive(Clone, Copy, PartialEq, Eq)] pub struct PhysicalAddress(pub u64);

fn read_block(address: PhysicalAddress) -> Block;
// read_block(LogicalAddress(value)) 直接编译不过 —— 一整类运行期 bug 变成编译期错误
```

再进一步，**把「还没验证过」也做成类型**，让「忘了验证」写不出来：

```rust
// ✗ 用布尔字段表达状态：忘了检查它，编译器不管
struct Node { bytes: Vec<u8>, is_checksum_verified: bool }

// ✓ 用类型表达状态：没验过的东西拿不到验过的那个类型
struct RawNode(Vec<u8>);        // 刚从盘上读出来，未验证
struct VerifiedNode(Vec<u8>);   // 校验和已比对通过

impl RawNode {
    fn verify(self, expected_checksum: Checksum) -> Result<VerifiedNode, CorruptBlock> { /* ... */ }
}

fn walk(node: &VerifiedNode) { /* ... */ }   // 想跳过验证就构造不出入参
```

- 同一种底层类型承载不同含义（逻辑地址、物理地址、代号；字节数、块数），各给一个 newtype。
- 「验没验过」「落没落盘」这类状态做成类型，不做成布尔字段。**边界上验一次**，换成带着证明的类型，
  往里就信类型，不在每一层重复检查。
- **布尔参数换成枚举**：`write(node, true)` 在调用点什么都没说，`write(node, Durability::Synced)` 说了。
- **封装是为了守不变量，不是为了藏。** 有不变量的字段私有，只能从检查过的构造函数进来；
  没有不变量的字段直接公开，不写样板 getter / setter。
- **带不变量的类型不实现 `Default`**：一个没经过检查就造出来的值，正是这个类型要挡的东西。
- **构造我们自己的结构体时，每个字段都写出来**，不用 `..Default::default()`。
  它是字段上的通配臂：新加一个字段，没写到的地方安静地拿到默认值。每个字段都写出来，漏一个编译不过。
  必填的字段不交给 builder 在运行期查，写成构造函数参数；只有真可选的才进 builder。
- **会丢值的数值转换不用 `as`。** `as` 截断、丢符号、回绕都不报错；会丢值的方向用 `try_from` 并处理失败，
  不会丢值的方向用 `from`。

**分支和类型是同一件事的两面**：一个让「漏掉一种情形」被编译器抓住，一个让「非法组合」写不出来。
两者都是把检查从人转给机器。

## 错误：能恢复的写进类型，破坏不变量的就断言

- **能恢复的失败**（I/O 错、盘上数据损坏、资源不够）**走 `Result`**。错误枚举的成员**按调用方要做的决定分**，
  不按底层原因逐个展开：上层真正要分流的，可能只有「没找到」「数据损坏」「空间不够」「其它 I/O 错」几种，
  底层几十种系统错误挂在「其它 I/O 错」那个成员里当 source 带着。调用方 `match` 它，漏处理一种编译不过。
- **判据是调用方有没有因此失去该有的决定。** 库代码的公开边界不用 `anyhow`、`Box<dyn Error>` 这种统一错误类型：
  它把「重试、报损坏、报空间不够」揉成一团，调用方没法分流，这是错误上的通配臂。
  反过来，把每一种底层失败都在每一层重新展开成一个成员也不对：成员一多，要紧的那几种反而被埋掉。
  测试和命令行工具可以用统一错误类型。
- **不变量被破坏是 bug，用断言**，不带着坏状态往下跑、更不往盘上写。
- **不写 `unwrap()`，写 `expect`**，消息写清它依赖哪条不变量：
  `expect("journal 头在 open() 里验过；这里是 None 说明验证被跳过了")`。它就是一条带名字的断言。

## 函数与嵌套：按「能单独验证」切，按路径数限

**函数的长度按「一件能单独验证的事」定，不按屏幕高度定。** 一件事写三百行可以；
两件事挤在二十行里要拆开。

**嵌套层数不设限，限的是路径数。** 「嵌套不超过三层」量错了东西：

| | 路径数 | 可测吗 |
|---|---|---|
| 12 层 `for` 遍历一个 12 维结构 | **1** | 控制流上完全可测；循环体里的状态另外验 |
| 12 层独立 `if/else` | **2¹²** | 测不完 |
| 3 层独立 `if/else` | 8 | 勉强 |

不带提前出口的循环嵌套几乎不增加路径（`break`、`continue`、`?` 每个都会添一条），条件嵌套按指数增加。
旧规矩把两者一起限死，是因为人读起来一样费劲——那是人的约束，不是验证的约束。
所以层数随意，只要两条都满足：路径数说得出、而且有限；
每一层的迭代对象有名字、有类型，不是 `a[i][j][k][l]`。那种写法的毛病不是深，是不带信息。

**路径数只量控制流，不是验证难度的全部。** 循环迭代多少次、每一轮带到下一轮的状态、提前出口、
嵌套循环之间的数据依赖，都能让要验的空间变大，而路径数一条也不会多。
所以路径数是控制流复杂度的硬指标：超了就拆；没超不等于好验。循环还要另外写清三件事：
迭代次数的上界、跨轮携带的状态和它的不变量（写成断言）、每一个提前出口。
**「只有一条路径」不能拿来给一个难验的算法辩护。**

- **参数不按个数限。** 每个参数有名字、有类型就行；只有几个参数本身构成一个带不变量的概念时，
  才收成一个类型，不为了让签名变短而凑结构体。
- **结果放进返回类型**，不用 `&mut` 输出参数传回：数据往哪流，写在签名上。
- **副作用挤到边上，核心写成纯函数。** 纯函数能穷举、能拿模型对拍；带 I/O 的外壳要靠崩溃点重放才验得了，
  所以越薄越好。一个函数既查又改，名字要把两件事都说出来。
- **提前返回随便用。** 单一出口是给人跟控制流用的；我们数的是路径，不是出口。

## 注释、断言、常量、重复

- **注释只写「为什么这样」**，不写「这在做什么」，后者机器自己看得懂。
  约束写进类型、名字或断言，不写进注释：注释会和实现脱节，名字和类型不会。
- **文档注释写类型表达不了的契约**：会返回哪些错、什么时候 panic、`unsafe` 要调用方保证什么。
  复述名字的文档注释删掉。
- **每个 `unsafe` 块上面写 `// SAFETY:`**，说清为什么安全。这是一条写不进类型的不变量，只能写进注释。
- **不变量写成断言**，不只写进文档。
- **魔法数字写成命名常量**：一个数只许有一处定义，名字或类型里带上单位。
- **重复要生成，不许手抄。** 同步改多处是机器的强项，前提是那几处出自同一个生成器：
  生成的重复不会分叉，手抄的会。宏和 `build.rs` 是生成的正路，但只做生成、不藏逻辑，
  生成出来的东西要有测试盯着——宏展开出来的名字，命名检查看不见。
- **用不到的代码删掉**，注释掉的代码也删：git 找得回，留着的是没人跑的路径。
  编译器报的 `never used` 当错误处理（`command-safety.md`：警告是免费的信号）。
- **`TODO` 写清缺什么、为什么现在不做。** 欠着的检查记进项目 kb 的欠账表，代码里指过去；
  光一句「TODO: 以后改」，没人会回来。

## 逐条审过的流行做法

每一条都照 `machine-first.md` 的流程过了一遍：它当初解决什么问题，那个问题今天还在不在，
有没有第二个理由。**处置**只有六种：废弃、放宽、改写、留下（理由改写）、交给工具、降为建议。

### 整体理念

| 流行做法 | 出处 | 当初解决什么 | 处置 | 我们的写法 |
|---|---|---|---|---|
| 代码读的次数比写的多，要为读的人优化 | 《Clean Code》等 | 人要维护代码 | **改写** | 读代码的主要是模型：为机器验证和信息量优化；人的注意力留给测试对不对、不变量对不对、依据成不成立、取舍要不要（`engineering-philosophy.md`） |
| 别写聪明的代码 | 通行说法 | 人看不懂 | **留下，理由改写** | 聪明的通用路径会吃掉穷尽性检查，漏了情形没人报警 |
| KISS，保持简单 | 通行说法 | 人装得下 | **改写** | 简单指控制流路径少、要验的状态少、每条路径都写明，不指行数少 |
| YAGNI，用不到的别写 | 极限编程 | 人的时间 | **留下，理由改写** | 用不到的代码就是没人验的路径 |
| 最小惊讶原则 | 通行说法 | 用的人猜得到它做什么 | **留下，理由改写** | 名字和类型要让模型猜对行为；猜错了，就是名字或类型没带够信息 |
| 约定优于配置 | Rails 等框架 | 少写配置 | **废弃** | 隐式的默认行为是看不见的路径：要的值都写出来 |
| 关注点分离、高内聚低耦合 | 通行说法 | 人一次只想一件事 | **留下，理由改写** | 一块能单独验证，靠的是边界清楚、契约明确 |
| 文件、模块不要太长 | 通行说法 | 人翻不动 | **放宽** | 模块按契约切，不按行数切 |

### 命名

| 流行做法 | 出处 | 当初解决什么 | 处置 | 我们的写法 |
|---|---|---|---|---|
| 名字要短，离声明越近越短 | Go 代码评审意见、Linux 内核编码风格 | 行宽和人的短期记忆 | **废弃** | 长度不设限，见「名字」 |
| 循环计数叫 `i`，临时变量叫 `tmp` | Linux 内核编码风格 | 省字，约定俗成 | **废弃** | 按它是什么命名：`stripe_index`、`unflushed_block` |
| 泛型参数用 `T`、`U`，生命周期用 `'a` | Rust 惯例 | 省字 | **废弃** | 按角色命名：`Key`、`Value`、`'journal` |
| 大家都认得的缩写可以用 | 通行说法 | 省字 | **废弃** | 写全；领域缩写登记之后才能用 |
| 名字要念得出来 | 《Clean Code》 | 人口头讨论 | **废弃这条理由** | 要的是不歧义、搜得到；不缩写自然念得出来 |
| 名字要搜得到 | 《Clean Code》 | 人在编辑器里找 | **留下，而且更硬** | grep 是模型找东西的主要办法：一个语义概念一个名字，全仓搜一次就全 |
| 匈牙利命名法、`m_` 前缀、接口名加 `I` | C / C++ / C# 旧惯例 | 编辑器里看不到类型 | **废弃**，它想做的事交给类型 | 含义不同就是不同的 newtype；类型表达不了的单位写进名字 |
| 不用 `Manager`、`Helper`、`Data`、`Info` 这类噪音词 | 《Clean Code》等 | 不带信息 | **留下** | 删掉它名字没少说什么，就说明它本来什么也没说 |
| 模块名别在类型名里重复（`block::Address`） | clippy 的 `module_name_repetitions`、Go 的包命名惯例 | 全路径读着啰嗦 | **废弃** | 名字自己站得住：写 `BlockAddress`。有意让名字带命名空间的信息，认类型名变长的代价 |
| 取值方法不加 `get_` 前缀 | Rust API 指南 C-GETTER | 与标准库一致 | **留下，理由改写** | 约定一致，检索和机器检查才靠得住 |
| 转换方法按 `as_`、`to_`、`into_` 命名 | Rust API 指南 C-CONV | 与标准库一致 | **留下，理由改写** | 前缀带着信息，但它是约定，编译器不查：`as_` 借用到借用、约定几乎无开销；`to_` 约定有开销，多半产出新值，也有 `to_str` 这种借用出借用的；`into_` 消费所有权。以 C-CONV 那张表为准，实现要兑现名字所说的那一类开销 |
| 布尔名以 `is_`、`has_` 开头 | 通行说法 | 读起来像句子 | **留下，理由改写** | 说清哪一边为真 |
| 类型用名词、方法用动词 | 《Clean Code》 | 读起来像句子 | **留下，理由改写** | 词性就是信息：名词说它是什么，动词说它做什么 |
| Rust 的大小写约定（`snake_case`、`CamelCase`） | Rust 惯例，rustc 默认警告 | 一眼分出类型和值 | **留下，理由改写** | 约定一致，机器检查才生效 |
| 同名遮蔽（`let text = text.trim()`）是惯用法 | Rust 惯例 | 少起一个名字 | **改写** | 含义不变可以遮蔽；换了含义就换名字。含义无关的遮蔽由 clippy 拦 |
| 测试函数叫 `test_<被测函数>` | 通行惯例 | 一眼找到测的是谁 | **废弃** | 写场景和预期结果 |

### 函数

| 流行做法 | 出处 | 当初解决什么 | 处置 | 我们的写法 |
|---|---|---|---|---|
| 函数要短：一两屏，最好不到 20 行 | 《Clean Code》、Linux 内核编码风格 | 屏幕高度和短期记忆 | **留下，理由改写** | 按「一件能单独验证的事」切，不按行数 |
| 只做一件事 | 《Clean Code》 | 人一次只想一件事 | **留下，理由改写** | 一件事才有一个能单独验证的契约 |
| 每个函数只有一个抽象层次 | 《Clean Code》 | 读着顺 | **放宽** | 不强求；要紧的是契约清楚、路径数有限 |
| 从上往下读（下沉规则） | 《Clean Code》 | 人从头读 | **废弃** | 模型检索着读，不按顺序读 |
| 参数最多三个 | 《Clean Code》 | 调用的人记不住顺序 | **放宽** | 每个参数有名字、有类型就行；成概念才收成类型 |
| 不用标志参数 | 《Clean Code》 | 读的人记不住 `true` 指什么 | **留下，理由改写** | 调用点那一行要自己带信息：换成枚举 |
| 不用输出参数 | 《Clean Code》 | 读的人以为是输入 | **留下，理由改写** | 结果放进返回类型，数据往哪流写在签名上 |
| 函数没有副作用；函数式核心、命令式外壳 | 《Clean Code》、Gary Bernhardt | 暗中改掉的状态坑人 | **留下，理由改写** | 纯函数能穷举、能对拍；I/O 挤到外壳，外壳靠崩溃点重放验 |
| 查询与修改分开 | Bertrand Meyer（CQS） | 调两次结果不同，让人意外 | **留下，理由改写** | 既查又改的函数，名字把两件事都说出来 |
| 单一出口 | 结构化程序设计 | 人跟得上控制流 | **废弃** | 提前返回随便用，数的是路径不是出口 |
| 嵌套不超过三层 | Linux 内核编码风格 | 人一层层解析很费劲 | **放宽** | 层数不限，限的是控制流路径数；循环的状态另外验 |
| 圈复杂度不超过某个数 | McCabe，各类静态分析工具 | 分支多了人看不过来 | **改写** | 穷举 `match` 的臂数不算，编译器替你数着；限的是彼此独立的条件 |

### 类型、数据与封装

| 流行做法 | 出处 | 当初解决什么 | 处置 | 我们的写法 |
|---|---|---|---|---|
| 用值对象代替基本类型 | 《重构》（基本类型偏执） | 业务含义 | **留下，而且更硬** | 含义不同就是不同的类型 |
| 让非法状态写不出来 | Yaron Minsky | 少写检查 | **留下** | 见「类型」 |
| 解析，而不是校验 | Alexis King | 校验完的结论丢了 | **留下** | 边界上验一次，换成带证明的类型，往里信类型 |
| 字段私有，配上 getter / setter | Java 系的封装惯例 | 以后好改实现 | **改写** | 封装是为了守不变量：有不变量的私有，没有的直接公开 |
| 默认不可变 | Rust 惯例、函数式编程 | 少出错 | **留下，理由改写** | 状态少，要验的组合就少 |
| 不用全局可变状态；不用单例 | 通行说法、《设计模式》的反面教材 | 追不到谁改了它 | **留下，理由改写** | 它让局部推理失效、测试不可复现 |
| 能 derive `Default` 就 derive | Rust 惯例 | 少写代码 | **改写** | 带不变量的类型不实现 `Default` |
| 结构体更新语法 `..Default::default()` | Rust 惯例 | 少写字段 | **我们自己的结构体上废弃** | 它是字段上的通配臂：每个字段都写出来，漏一个编译不过 |
| 字段多就上 builder | Rust API 指南 C-BUILDER | 可选参数多 | **改写** | 必填的写成构造函数参数，编译期逼着给；只有真可选的才进 builder |
| 数值转换用 `as` | C 系惯例 | 写着短 | **会丢值的方向废弃** | 用 `try_from` 并处理失败，由 clippy 拦 |
| 别用 typedef 给结构体换个名字 | Linux 内核编码风格 | 读的人看不出它是结构体 | **废弃** | newtype 要的就是包一层：包的是含义，不是藏结构 |
| 魔法数字要起名 | 通行说法 | 读的人不知道这个数是什么 | **留下，理由改写** | 一个数只许有一处定义，名字或类型带单位 |

### 分支与抽象

| 流行做法 | 出处 | 当初解决什么 | 处置 | 我们的写法 |
|---|---|---|---|---|
| 用多态替换条件分支 | 《重构》 | 加一种情形不改旧代码 | **封闭集合上废弃** | `enum` 加穷举 `match`，见「分支」 |
| 开闭原则 | SOLID | 加功能不改旧代码 | **封闭集合上废弃** | 我们要的恰恰是：加一种情形，编译器逼着把每一处旧代码过一遍 |
| 单一职责 | SOLID | 一个类只有一个改动的理由 | **留下，理由改写** | 一块只有一个能单独验证的契约 |
| 里氏替换 | SOLID | 子类能顶替父类 | **留下，理由改写** | trait 的契约对每个实现都成立：契约测试对每个实现都跑，与「阳性对照每条臂都跑」是同一件事（`test-discipline.md`） |
| 接口隔离 | SOLID | 不被迫依赖用不到的方法 | **留下，理由改写** | trait 越小，每个实现要验的契约越小，默认方法（通配臂）越少 |
| 依赖倒置：依赖抽象，不依赖具体 | SOLID | 好替换、好 mock | **改写** | 至少两个真实现才抽 trait，对拍用的模型算一个 |
| 迪米特法则：只和直接的朋友说话 | Northeastern 大学 Demeter 项目 | 改结构时牵连少 | **放宽** | 模块内部随便链；跨模块不许穿过别人的内部，那是在绕开契约 |
| 设计模式：工厂、策略、访问者 | 《设计模式》 | 复用一套结构 | **改写** | 策略、访问者在封闭集合上就是 `match`；为模式而模式多出来的一层，是没人验的开放集合 |
| DRY，避免重复 | 《程序员修炼之道》 | 改一处要同步改多处 | **放宽** | 同步改多处是机器的强项，但重复要生成，不许手抄 |
| 三次重复之后再抽象 | 《重构》（Don Roberts） | 抽错了代价大 | **留下，理由改写** | 抽出来的通用路径会吃掉穷尽性检查；重复先交给生成器 |
| `default:` / `_ =>` 兜底更稳 | 防御式编程 | 漏了情形不至于崩 | **封闭集合上废弃** | 漏掉的情形交给编译器抓；允许未知值的，把「未知」做成显式成员 |

### 错误处理

| 流行做法 | 出处 | 当初解决什么 | 处置 | 我们的写法 |
|---|---|---|---|---|
| 快速失败 | 《程序员修炼之道》 | 别带着坏状态往下跑 | **留下** | 不变量被破坏就断言，不往盘上写坏状态 |
| 库代码不 panic，一律返回 `Result` | Rust 惯例 | 调用方能恢复 | **改写** | 能恢复的走 `Result`；不变量被破坏是 bug，用断言 |
| 用 `anyhow`、`Box<dyn Error>` 统一错误类型 | Rust 生态惯例 | 少写错误类型 | **库代码的公开边界上废弃** | 调用方没法分流：成员按调用方要做的决定分，底层原因当 source 带着 |
| 确定不会失败时用 `unwrap()` | Rust 惯例 | 少写一句 | **废弃** | 用 `expect`，消息写清依赖哪条不变量 |
| 防御式编程：处处检查参数 | 通行说法 | 挡住坏输入 | **改写** | 边界上查一次，换成带证明的类型，往里不重复查 |
| 错误码还是异常 | 各语言之争 | 各有代价 | **交给类型** | 失败写进返回类型，编译器逼着处理 |

## 什么时候不套用

**这些细则对「删得掉的东西」随便用，对「删不掉的东西」要另说。**
代码里的名字、分支、类型写错了可以改；写进对外承诺的东西（磁盘格式、协议、公开 API）改不掉，
以后每一个实现都得永远支持它。那一边的判据要单独定，不能拿一句「显式更安全」推过去。

## 门禁管哪一半

| 细则 | 谁查 |
|---|---|
| 单字母名、常见缩写 | `scripts/naming-lint.sh`（门禁阶段「命名纪律」）：扫项目里每个 `.rs`，只看我们声明的名字 |
| 封闭集合的枚举不写 `_ =>` | clippy `wildcard_enum_match_arm`；声明开放的，在那一处 allow 并写 reason |
| `#[allow]` 要写 `reason = "…"` | clippy `allow_attributes_without_reason` |
| 会丢值的 `as` 转换 | clippy `cast_possible_truncation`、`cast_sign_loss`、`cast_possible_wrap` |
| `unsafe` 块要有 `// SAFETY:` | clippy `undocumented_unsafe_blocks` |
| 含义无关的同名遮蔽 | clippy `shadow_unrelated` |
| 警告按错误处理 | clippy `-D warnings` |
| 名字说没说清、一个概念是不是一个名字、函数是不是只做一件事、注释写的是不是为什么、错误成员是不是按调用方的决定分的、循环的状态有没有写清、`..Default::default()` | review。这些机器判不了，或者还没有现成的检查 |
| shell 脚本里的名字 | **还没做成检查**，`gate.sh` 把它列在未实现的阶段里 |

clippy 那几条由 `scripts/check.sh` 带着跑，也就是门禁的「构建与单测」阶段；项目根没有 `Cargo.toml` 时这一阶段不跑。

`naming-lint.sh` 的缩写词表只列最常见的那些，**词表外的缩写照样违规**，只是门禁看不见。
它认不出的形态（跨行的模式、宏展开出来的名字）不判，交给 review，认不出不等于通过。
trait 实现里的方法名、关联类型，以及 `extern` 块里的声明，名字是外部定的，不查。

项目侧两份配置，一行一条，`#` 后面写理由，理由不许省：

| 文件 | 管什么 |
