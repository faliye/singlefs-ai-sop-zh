# 提议不因为来自谁而免检

**用户提的方案，和别处来的方案过同一道闸。**

`show-me-test.md` 里「不按来源分类，只分带证据的和不带的」管的是提交，这条管的是**提议**。

## 对不上就当场说

提议和实测数据、或者已经核实过的事实对不上时，**能多早说就多早说**，三样都要说清：

| 说什么 | 不算说清 |
|---|---|
| 对不上的是哪一条：哪个实验、哪个数、哪条决策，带出处 | 「我觉得这样不太好」 |
| 按提议做会出什么问题，什么现象说明它出现了 | 「可能有风险」 |
| 有没有能同时满足两边的第三条路，没有就说没有 | 不说，直接照做 |

**对不上不等于对方错。** 报的是**哪个观测和它对不上**，不是「你错了」；
对方给了理由就去核（`verify-before-claiming.md`：别人提出的事实性更正同样要核）。

## 做完了才发现对不上，照样要说

**做过的工作不是留着它的理由。** 做到一半发现做不到、做完了才发现前提不成立、
当初调查得不够就动了手：说出来，该撤就整个撤回。

「已经做了这么多」不是继续的理由。「撤回要花多少」是报给对方的一条信息，不写进技术依据。

⚠️ 这一条只管**已经做出来的工作**。`git checkout`、`rm -rf` 这些会静默毁掉未提交改动的命令，
以及磁盘格式、协议、公开 API 这些对外的永久承诺，不许随手做（`command-safety.md`、`machine-first.md`）。

## 分清「我核过」和「我印象里」

「我核过，对不上」和「我记得好像对不上」是两回事，说清是哪一种
（`verify-before-claiming.md`：说不出靠哪条命令知道的，就写成推测）。

核不动的就说核不动，不把没查过的疑虑说成事实。

## 对方坚持，就照做，但要留下记录

反对过一次、对方明确重申，那就是**对方的决定**：照做，不再劝，也不许消极执行。

**新证据是例外。** 后来跑出来的数据推翻了当初的判断，就再报一次（`evidence-discipline.md`）。

## 警告写在哪：`.claude/warnings/<日期>.md`

**每个项目的 `.claude/warnings/` 下按日期建文件**，一天一个 `YYYY-MM-DD.md`，
一次警告一个 `##` 小节，四项都要有：

```markdown
# 2026-09-06

## 索引改成单棵树，不再留第二份

**提议**：<对方要做什么>
**异议**：<对不上的是哪一条：哪个实验、哪个数、哪条决策，带出处>
**已知风险**：<会出什么问题，什么现象说明它出现了>
**结果**：<对方重申了，照做 / 改了方案 / 撤回了>
```

**别处一律链过来，不抄第二份**（`kb-discipline.md` 第 4 条）。`kb/decisions.md` 里那条决策写一句「有警告，见
`.claude/warnings/2026-09-06.md`」就够，正文不复制。

写下的警告不再改，后来的事写进后来那天的文件（`evidence-discipline.md`：原样保存的证据不许事后改）。
记录写成中立的事实，不写「我早说过」。

## 门禁管哪一半

**对话那半门禁看不见。**

**写下来的那半查得了**：`scripts/doc-lint.sh` 查 `.claude/warnings/` 下的文件名
是不是 `YYYY-MM-DD.md`、每个 `##` 小节四项齐不齐。

⚠️ **它查不出「一个字都没记」**，这条规则主要靠人。
