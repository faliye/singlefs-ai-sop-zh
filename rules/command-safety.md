# 进程与命令规范

有七条是会红的检查，由 `scripts/shell-lint.sh` 判：
**按模式匹配杀进程**（`pkill -f`、`killall`）、**`pgrep -f`**、**靠子 shell 里的赋值往外带值**、
**脚本里用 git 的撤销命令**、**`rm -rf` 作用在没守卫的变量路径上**、**不带参数的 `wait`**、**设了 `pipefail` 的脚本里以 `grep -q` 收尾的管道**。
测试装置跑完删没删自己建的镜像，由 `gate.sh` 的「跑完没留下临时文件」判。
其余几条还只是文字，怎么用机器判还没想清楚（`show-me-test.md` 的「门禁能证明什么，不能证明什么」）。

## 退不回去的操作，动手前先想一遍

判据：**这一步做完，还能不能退回去？**

| 类型 | 例子 | 怎么办 |
|---|---|---|
| **丢掉未提交的改动** | `git checkout <文件>`、`git restore`、`git reset --hard`、`git clean` | 先 `git stash` 或 `cp` 一份出去；只在明确要丢掉这个文件的全部未提交改动时才用 |
| **直接删数据** | `rm -rf`、`> 文件`、`sed -i`、`rsync --delete`、`mkfs`、`dd` | 先看清目标（`ls`/`git status`/`lsblk`），变量路径加 `${VAR:?}` 守卫 |

**临时试验在副本里做**，别在工作区改了再撤。

**脚本里一律不许出现 git 的撤销命令。** 要在脚本里回到干净状态，就先 `git stash`，
或者把整个仓拷一份出来在副本上做。

**`rm -rf` 作用在变量路径上要加空值守卫**：写成 `rm -rf "${d:?}/x"`，不写 `rm -rf "$d/x"`。
`rm -rf "$d"` 这种后面不跟路径的不用管。

## `pkill -f` / `killall` 一律禁用

要停进程就先 `ps` 列出来看清楚，再用**写死的 pid** 另起一条命令去杀；
也可以交给 `scripts/proc.py stop 进程号`：它先发 TERM，过 `--grace` 秒（默认 10）还在再发 KILL，要停的是发出命令的进程自己或它的祖先时拒绝。
统计类的改用 `/proc` 里的结构化信息，并且排掉自己这一支进程树。

**等待循环里同样不用 `pgrep -f`**（`until ! pgrep -f "X"; do sleep 5; done` 这种）。
等一个进程结束，用它**写死的 pid**：`until ! kill -0 "$pid" 2>/dev/null; do sleep 5; done`；
等自己起的后台任务用 `wait`；不是自己起的（别的脚本拉起来的守护进程之类），让起它的一方把 pid 写进文件再等。
pid 没记下来的，用 `scripts/proc.py find 可执行文件名 [--argument 参数]` 找进程号：它按可执行文件名逐字比，不拿模式串去比整条命令行，也不列发出这条命令的那一支进程；
拿到进程号再 `scripts/proc.py wait 进程号 --timeout 秒` 等它退出，到点还没退出就列出还活着的、退出码 3。
`scripts/shell-lint.sh` 的 S3 那条对脚本里命令位置上的每一处 `pgrep -f` 都红（`if` / `while` / `until` / `!` 后面也算命令位置），
不看同一行还有没有 `kill`。
手敲的命令由 `scripts/claude-hooks/pattern-process-guard.sh` 在执行前拒绝，判据与 shell-lint 的 S2、S3 是同一份（`scripts/lib.sh` 的 `PATTERN_KILL_RE`、`PATTERN_PGREP_RE`），
拒绝时给出按进程号办事的写法。它是 Claude Code 的 PreToolUse 钩子，项目在 `.claude/settings.json` 的 `hooks.PreToolUse` 里注册一次：

```json
{"matcher": "Bash", "hooks": [{"type": "command", "command": "bash \"$CLAUDE_PROJECT_DIR\"/.claude/singlefs-ai-sop/scripts/claude-hooks/pattern-process-guard.sh"}]}
```

没注册的会话里，手敲的命令仍然只靠这一条文字。

## 起了后台任务和子 agent，就要定时复检，不强制结束

长活可以等，但要有人看着：

- **起了就要复检。** 后台起的任务、派出去的子 agent，调度的一方定时看：最后一次动作是多久以前、是不是停在等待循环里、
  同一条命令是不是反复跑而输出一模一样、它写的文件还涨不涨。
- **检出和处置分开。** 检出卡住与空转的工具（hook、看门狗脚本）只记录、只报告，不拦命令、不杀进程、不停子 agent；
  结不结束、怎么处置，由调度的一方看了再定。
  拒绝某一种危险写法的钩子不在此列（`session-wrapup.md` 第 4 条：写入前拒绝覆盖未跟踪的文件）。
- **等日志里的一行字之前，先确认那一行真会写进那个文件。**
- 在 Claude Code 这类会话里，长活放后台，定期回来复检，不在前台干等。

## 一个脚本里的检测项，能并行就并行

**判据：这一批检测项互不依赖，而每一项都要起子进程干活（编译、跑测试、起虚机、起 python），
那就并行跑，别逐个等。**

快下来之后再看一眼剩下的时间花在哪：故意空等的用例（比如验的就是「超时逻辑被破坏之后 `wait` 不返回」）并行省不掉。

**这三种不并行**：

- 后一项要读前一项的产物；
- 共用一份可写状态（同一个临时目录、同一个 target 目录、同一台设备）。要并行就每项各给一份；
- 每项本身就快，一项只跑几毫秒。

并行度（进程数，以及进程内的线程数）从参数或环境变量取，没给就按 `nproc` 取，别写死；跑虚机、跑编译这种重活另外按内存和设备定上限。
共享脚本起的 cargo（`scripts/check.sh`）经项目根 `.claude/cargo-command-prefix` 登记的前缀跑：一行 `<命令与参数>  # 理由`，
按空白切成词、不认引号，相对路径从项目根算，每一条 cargo 各自经它一次。文件在而读不出一条能用的前缀就判红，不退回无包装去跑：
像路径的词（带 `/`，或以 `.sh`、`.py` 结尾；`-` 开头的选项与带 `=` 的赋值不算）要存在，前缀先空跑一次（`<前缀> true`）要成功；`gate.sh --staged` 时源仓有这份登记、HEAD 加暂存区里没有，也判红。

## 并行不许把失败吃掉

收束只有两种写法：起的时候记 `pids+=($!)`、收的时候逐个 `wait "$pid"` 取退出码；
或者并行的每一项各写一个退出码文件，收的时候按派活时那张表的顺序逐个判。
不带参数的 `wait`、后台体里写 `|| bad=1` 再由父进程读 `$bad`，都收不到退出码。

`scripts/shell-lint.sh` 的 S6 判这一条：命令位置上不带参数的 `wait` 判红。
退出码确实在别处收了的，在那一行写 `# shell-lint:exit-collected <怎么收的>`，理由不许省。

**并行的每一项，输出不许直接往 stdout 写。** 每项写自己的文件，收的时候按派活的顺序回读。

**派出去多少项，就要收回来多少项。** 收的时候数一遍，与派出去的条数对不上就整道红。

**改成并行之后要重新证明它红得出来。** 照 `show-me-test.md` 做：拿一个必红的输入喂进去，看并行版本还红不红。

## 别用 echo 假装命令成功

不写 `cmd 2>/dev/null; echo "已完成"` 这种报成功的方式。
凡是改状态的命令，都要**回头读一次实际状态**来确认：
`systemctl stop X` 之后跑一下 `is-active`，不能只看 stop 的退出码。

## 结果抓取要有完整性闸

**做法**：被测程序在最后一行报出它总共发了多少条，抓取方比对条数，对不上就整轮作废。
这道闸自己也要先证明会红：喂一个声称发 N 条、实际只发 N−1 条的假程序，它必须判红。

## 带闸的脚本，判完了才交出产物

一个脚本既产出结果、又负责判它能不能用时，**产物要等判完才交给调用方**。

**做法**：结果先写临时文件，闸过了再输出；判红时 stdout 保持为空。
这道闸同样要证明会红：把脚本改回「先输出、后判」，自证必须判红。

## 子 shell 里的赋值传不回父进程

`rc="$(run_one ...)"` 这种写法里，`run_one` 内部给变量的赋值**在父进程里是空的**。
**要传值就落到文件或者走参数，别靠变量。** 它是 `scripts/shell-lint.sh` 里会红的一项。

## 脚本改文件之后要回读确认，警告是免费的信号

用脚本做字符串替换来改代码或文档，两条做法：

1. **替换必须断言命中**：替换数为 0 就报错退出，不许「改完就当改了」。
2. **改完回读**：grep 一下新内容在不在，或者直接跑一遍看行为变没变。

**编译器和 linter 的警告不许略过。**

## 进程边界上的三种静默失效

| 形态 | 怎么写 |
|---|---|
| `set -e` 下写 `里层; rc=$?` | 退出码在 `if` 里取：`if 里层; then rc=0; else rc=$?; fi` |
| `export X="$(cmd)"` / `local x="$(cmd)"` | 先赋值再 `export`，两行写 |
| 握手用的环境变量漏给子进程 | 读完就 `unset`；起子进程时 `env -u` 清掉 |

**判据是「这个值跨了几层进程」**：跨一层就要问它在下一层还在不在、该不该在。

## 管道里的退出码不是你想要的那个

`cmd | head` 之后的 `$?`、`cmd | grep x && do_something`，判的都是管道最后一段，不是 `cmd`。

**做法**：想判前一段成没成，用 `${PIPESTATUS[0]}`，或者干脆别接管道——
先把输出落到变量或文件里，判完退出码再处理。

`scripts/shell-lint.sh` 的 S7 判其中一种：设了 `pipefail` 的脚本里，以 `grep -q` 收尾的管道（`… | grep -q 模式`）判红，命中会被读成没命中。
改法：先把前段的输出落到变量，再 `grep -q 模式 <<<"$变量"`；这种没有前段的写法不判。

## 测试镜像一律放临时目录

不许放在仓库里。镜像路径统一从环境变量取，默认落到 `${TMPDIR:-/tmp}`。

**建镜像的装置在测试结束时自己删掉它**：成功、失败、panic 都删。Rust 用 Drop 守卫，shell 用 `trap … EXIT`。
要留着看现场，由显式的开关（环境变量）打开，留下时打印路径；没打开就删。
门禁阶段判红时可以把现场留在 `$TMPDIR` 里，出路里点它的路径。
有意跨轮复用的缓存（编译产物、判定库这类）不是镜像：放 `${GATE_CROSS_RUN_TMPDIR:-${TMPDIR:-/tmp}}` 下或项目定的位置，不放 `$TMPDIR`。

`gate.sh` 判这一条：每一轮给各阶段一个这一轮自己的 `TMPDIR`，收尾时看里面还剩什么（阶段「跑完没留下临时文件」）：
别的阶段都绿，剩下的判红、列出名字与大小，退出时替它们删掉；有阶段判红，这一项记本次未判，这一轮的临时目录整个留着、打印路径，看完自己删。
判红时这样留着的只留最近 3 个，更早的由之后跑的那一轮删掉。
它看不见的：路径写死 `/tmp`、不走 `TMPDIR` 的装置，门禁之外手跑的测试，以及门禁被打断之后还在跑的子进程建的。

## 破坏性操作先看清楚再动

`mkfs`、`dd`、`dmsetup remove` 这些命令，**目标设备必须从变量取，而且先 `lsblk` 打出来确认一眼**，不许直接写死 `/dev/sdX`。
