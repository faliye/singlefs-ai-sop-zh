# 进程与命令规范

下面有四条已经是会红的检查，不再只是提醒，由 `scripts/shell-lint.sh` 判：
**按模式匹配杀进程**、**靠子 shell 里的赋值往外带值**、
**脚本里用 git 的撤销命令**、**`rm -rf` 作用在没守卫的变量路径上**。
其余几条还只是文字，因为怎么用机器判还没想清楚
（见 `show-me-test.md` 的「门禁能证明什么，不能证明什么」——没做的事要说出来，不能含糊）。

## 退不回去的操作，动手前先想一遍

判据只有一句：**这一步做完，还能不能退回去？**

退不回去的两类，处理方式不一样：

| 类型 | 例子 | 怎么办 |
|---|---|---|
| **丢掉未提交的改动** | `git checkout <文件>`、`git restore`、`git reset --hard`、`git clean` | 先 `git stash` 或 `cp` 一份出去；只在明确要丢掉这个文件的全部未提交改动时才用 |
| **直接删数据** | `rm -rf`、`> 文件`、`sed -i`、`rsync --delete`、`mkfs`、`dd` | 先看清目标（`ls`/`git status`/`lsblk`），变量路径加 `${VAR:?}` 守卫 |

**实测踩过**：只是想撤销一个临时的 `sed`，用了 `git checkout <文件>`，
结果把同一个文件里当轮所有未提交的改动一起冲掉了。
那次是从 reflog 里一个刚被撤销的 commit 救回来的——如果那个 commit 不存在，就没救。

**所以：临时试验在副本里做**，别在工作区改了再想办法撤。

**脚本里一律不许出现 git 的撤销命令。** 脚本跑起来的时候没人在旁边看 `git status`，
而这些命令没有 undo。要在脚本里回到干净状态，就先 `git stash`，
或者把整个仓拷一份出来在副本上做。

**`rm -rf` 作用在变量路径上要加空值守卫。**
`rm -rf "$d/x"` 在 `$d` 为空时会变成 `rm -rf /x`；写成 `rm -rf "${d:?}/x"`，
变量为空时 shell 先报错退出，轮不到 `rm` 动手。
（`rm -rf "$d"` 这种后面不跟路径的不用管：为空时是 `rm -rf ""`，`rm` 自己会拒。）

## `pkill -f` / `killall` 一律禁用

那个模式串会出现在 wrapper 自己的命令行里，结果**把自己的 shell 也杀了**。

要停进程就先 `ps` 列出来看清楚，再用**写死的 pid** 另起一条命令去杀。
统计类的改用 `/proc` 里的结构化信息，并且排掉自己这一支进程树。

## QEMU 虚机必须把 pid 写进文件

销毁的时候按文件里那个写死的 pid 杀，不许按名字匹配。
虚机跑飞了会把内存占满，而按名字匹配会顺手杀掉别的测试。

## 别用 echo 假装命令成功

`cmd 2>/dev/null; echo "已完成"` 里那句 echo **不管前面成没成都会执行**，
sudo 失败了它照样打印「已完成」。

凡是改状态的命令，都要**回头读一次实际状态**来确认：
`systemctl stop X` 之后跑一下 `is-active`，不能只看 stop 的退出码。

## 结果抓取要有完整性闸

被测程序打印结果，外面的脚本抓回来——**这一路上丢一行是不会有任何提示的**。
控制台会被 BIOS 的转义序列、内核日志、串口噪声弄脏，
用 `grep '^ANCHOR'` 按行首去抓，行首被顶掉的那一行就悄悄漏了。
外面看到的是「少了一项」，不是「出错了」。

**做法**：被测程序在最后一行报出它总共发了多少条，抓取方比对条数，对不上就整轮作废。
这道闸自己也要先证明会红：喂一个声称发 N 条、实际只发 N−1 条的假程序，它必须判红。

## 带闸的脚本，判完了才交出产物

一个脚本既产出结果、又负责判它能不能用时，**产物要等判完才交给调用方**。
先把结果打到 stdout、再跑闸，调用方的重定向文件里就已经存下了一份被判作废的输出——
文件名是调用方起的，看着和合法的产物一模一样。退出码报了错，文件却留着，
下一个翻目录的人不会去查当时的退出码。

实测（2026-09-12）：一个取模型答复的脚本先 `print` 正文、再过字词损坏闸，判红时退出码 5、另存了一份作废副本；
调用方 `> …-output-s1.md` 那个文件里照样是那份正文，与作废副本只差一个换行。

**做法**：结果先写临时文件，闸过了再输出；判红时 stdout 保持为空。
这道闸同样要证明会红：把脚本改回「先输出、后判」，自检必须判红。

## 子 shell 里的赋值传不回父进程

`rc="$(run_one ...)"` 这种写法里，`run_one` 内部给变量的赋值**在父进程里是空的**。
如果抓结果要用到那个变量（比如日志路径），就会永远抓到零条，而退出码是 0——
又一次绿着灯出错。**要传值就落到文件或者走参数，别靠变量。**

在 `set -u` 下更糟：引用的地方拿到的不是空值，是当场报「unbound variable」，
**脚本还没来得及打印诊断就被带走了**。这事就发生在这个仓自己的 QEMU harness 里：
五处失败分支的 `howto` 一句都没打出来，而 harness 说谎的时候最该看的就是那几句。
写条注释提醒拦不住这种事，所以它现在是 `scripts/shell-lint.sh` 里会红的一项。

## 脚本改文件之后要回读确认，警告是免费的信号

用脚本做字符串替换来改代码或文档，**匹配不上是不会报错的，它就什么都不做**。
缩进差一个空格、引号换了个体、行尾多个空格，替换就悄悄失效了，而退出码是 0。

**两条做法**：
1. **替换必须断言命中**：替换数为 0 就报错退出，不许「改完就当改了」。
2. **改完回读**：grep 一下新内容在不在，或者直接跑一遍看行为变没变。

⚠️ **编译器和 linter 的警告是发现这类失效最便宜的信号，不许略过。**
实测：一次替换因为缩进对不上没生效，于是一个方法成了死代码，
编译器每次构建都在报 `never used`——这条警告被忽略了整整一轮，
而基于那段代码得出的结论**方向是反的**。

## 管道里的退出码不是你想要的那个

`cmd | head` 之后取 `$?`，拿到的是 `head` 的退出码，不是 `cmd` 的。
`cmd | grep x && do_something` 也一样，判的是 `grep` 成没成功。

结果就是**失败被吞掉**：`cmd` 其实已经挂了，脚本还往下走，
后面每一步都建立在一个根本不存在的结果上。

**做法**：想判前一段成没成，用 `${PIPESTATUS[0]}`，或者干脆别接管道——
先把输出落到变量或文件里，判完退出码再处理。

## 测试镜像一律放临时目录

不许放在仓库里。几个 G 的镜像一旦误提交进 git，收拾不回来。
镜像路径统一从环境变量取，默认落到 `${TMPDIR:-/tmp}`。

## 破坏性操作先看清楚再动

`mkfs`、`dd`、`dmsetup remove` 这些命令，设备名打错就会毁掉真实数据。
**目标设备必须从变量取，而且先 `lsblk` 打出来确认一眼**，不许直接写死 `/dev/sdX`。
