# 写作纪律

管所有写给人读的文字：规则、README、设计说明、kb、commit message、代码注释、门禁的失败信息。

## 文风要简单自然

**用自然的现代汉语写，平铺直叙，不绕弯子。**

### 四类不许写

| 不许写 | 什么样子 | 改成 |
|---|---|---|
| **翻译腔** | 「在……的情况下」「对……而言」「使得」「进行分析」「予以处理」 | 「……的时候」「对……来说」「让」「分析」「处理」 |
| **古风腔** | 「此乃」「是故」「然则」「殊为」「实乃」「不失为」 | 直接说这是什么、所以怎样 |
| **不必要的转折论述** | 「诚然……但是……」「虽然……然而……」，而两边根本不冲突 | 只留你真正想说的那一半 |
| **过度解释** | 「众所周知」「毋庸置疑」「不言而喻」，以及把一个结论正着说完再反着说一遍 | 说一遍就够 |

### 不写缩写，不用代号指东西

判据与登记表同 `code-discipline.md` 的「名字」一节与「注释里不写缩写，不用代号指东西」那一条。

门禁阶段「代号」（`scripts/code-name-lint.py`）判相对 diff 基准新加的 `.md` 行里两种形态：数字接一个小写字母（可再接 `-<字母或数字>`），两个大写字母接两位数字。反引号、围栏、HTML 注释、链接目标与网址里的不判，「第 1b 步」这类指编号步骤的不判；一份 `.md` 自己用 `<!-- doc-lint:not-numbers … -->` 声明过的标号，在这一份里不判，别的文件照判。
项目自己有登记位的编号体系（变异名、实验号），在项目根 `.claude/code-names` 登记：一行 `<正则>  # 理由`，代号整个匹配上就不判。
缩写、别的形态的代号、代码注释与 `.md` 以外的文本，门禁不查；基准里已有的行不回扫。

### 连词写成连词，名词串拆回句子

不用 `⇒`、`×`、`+` 替掉连词，不把动作压成「逐字核实四处必查」这种名词串。

- 该说「所以 / 因为 / 于是 / 但是」的地方就写连词，不用 `⇒`；表格单元格里空间紧，可以留符号。
- 名词串拆回句子：「主 agent 另行逐字核实四处必查」写成「另外我把四处必查的地方逐字核了一遍」。
- 粗体留给判决和数字，不整句整段加粗。
- 「机制：」「依据：」「口径：」这类标签式冒号在 kb 里可以留，冒号后面要跟完整的句子。

门禁阶段「代号」（`scripts/code-name-lint.py`）判 `⇒`：相对 diff 基准新加的 `.md` 行里有 `⇒` 判红，表格行与反引号里的不判。名词串、`×` 与 `+` 它不判；基准里已有的行不回扫。

### 判据

**念一遍。** 这句话你会对同事说出口吗？不会就改。

具体一点，三个问题：

- 这个词平时说话用吗？不用就换掉。
- 这一句在解释上一句吗？如果上一句已经说清楚了，这句删掉。
- 这个转折真的转了吗？前后不冲突就不要「虽然……但是」。

### 别矫枉过正

**说人话不等于说得含糊。** 术语、口径、数字、命令，该精确还是要精确：
「块大小 16 KiB」不能写成「块不大」。

**也不等于不许有判断。** 「这条不该定」「这个做法是错的」就直接这么写，
不先铺垫再拐进去。

### 门禁管哪一半

`scripts/doc-lint.sh` 查**词表里那些固定说法**（翻译腔和古风腔的常见构式），
命中就红，并给出替换建议。规则本体（`rules/*.md`、`CLAUDE.md`、skill 正文）一样查：
文件头的 `<!-- doc-lint:rule-definition -->` 只豁免反引号与「」里举的例子，正文照查。

**它管不了的**：句子顺不顺、转折是不是多余、解释是不是啰嗦，靠人念一遍。
词表全绿只代表没踩到词表里那几个坑。

词表是中文的，只管中文。英文、日文仓里这条检查**显式报未实现**，不假装通过（`show-me-test.md`：门禁不许假装通过）。
