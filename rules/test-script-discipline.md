# 测试用例与测试脚本的写法

管项目自己的验证代码：单元与集成测试、穷举与长时间随机的重型验证、真设备与外部工具的装置，以及入口脚本。入口脚本指把一批登记的项组织起来跑的脚本；对一张表、一份输入跑的工具（必须带位置参数的那种）与只读日志的辅助脚本不算入口脚本。
它们同样受 `show-me-test.md`（新测试先证明会红）、`test-discipline.md`、`command-safety.md`、`preflight-discipline.md` 管。

## 用例原子化：每一条都能单独跑

**判据：点名单跑一条用例，与它在全量里跑，判定相同。**

- 一条用例一个场景。按参数循环、每一轮重建被测状态的，拆成一个带参数的函数加每个取值一条用例；确是一个场景的（同一份状态上按次序做几步），在用例旁写一行注释说明为什么。
- 不依赖跑序，不读别的用例留下的状态：文件、全局变量、环境变量、临时目录。每条用例自己建、自己删（`command-safety.md`「测试镜像一律放临时目录」）。
- 随机输入带种子。红了打印种子，凭种子能单独复现那一条。
- 用例名写场景和预期（`code-discipline.md` 的「名字」），不带里程碑、步号、批次这类来历；来历进 commit message 或项目 kb。
- 红了只重跑红的那几条：入口脚本能从上一趟的输出里取出红的用例，给出只跑它们的命令。取出的条数与那一趟汇总报的失败数对不上，判红，不给命令，出路写「整份重跑一次」（`command-safety.md`「结果抓取要有完整性闸」）。

## 入口脚本：不带参数就是全量

| 参数 | 做什么 |
|---|---|
| 不带 | 全量：快档与慢档的全部项 |
| `--quick` | 只跑快档 |
| `--list-items` | 逐行列出可点名的项与它的档位，不编译、不跑 |
| `--item <项>` | 只跑点名的项，给几次取并集 |
| 项名写错、`--item` 后面缺项名 | 列出可点名的项，退 2 |

- 门禁阶段不是入口脚本：`gate.sh` 不带参数起阶段；阶段里直接起测试框架或调入口脚本，都显式写档位（`--quick`、`--item`，或测试框架自己的筛选参数）。
- 用测试框架自带的标记分档（`#[ignore]` 这类）时，不带参数也要把带标记的一起跑上（`--include-ignored`）。
- 规模变量（种子数、展开深度这类）被设过，这一趟的产物要写出它的取值；全量的完成标记不认缩过规模的那一趟。
- 整个脚本都离不开的工具、设备、硬件，写成 `run-condition`（`preflight-discipline.md`），不满足退 78；只有个别项要的，那几项照 `show-me-test.md`「门禁不许假装通过」逐项报「本次未跑」，这一趟不说「全量通过」。
- 每项结束打一行：项名、退出码、判了多少、红了多少、复用了多少（没有判定复用这一层的项写明「不复用」；有这一层、这一趟取不出数的写「取不出」，不并进总计，成功那句点名是哪几项；两种都不写 0）、用了几秒；末行是总计。收回的项数照 `command-safety.md`「并行不许把失败吃掉」核。
- 退出码 0 跑到的全绿（有项报了「本次未跑」也是 0）、1 有红、2 用法错、77 一项都没跑到、78 准入或运行条件不满足（`preflight-discipline.md`），这五个的含义固定；别的拒绝形态可以另用退出码，在文件头逐个列明。

## 测试脚本自己也要被测试证明有效

**判据：测试脚本与它用的判法，都有一份自证；把它们改坏，自证会红**（同 `test-discipline.md`「检查本身也可能是错的」，对象是项目的测试脚本）。

- 写成能被测的形态：判法写成纯函数，项的驱动、设备、时钟、随机源都能从参数或环境变量换成假的，不写死路径与外部服务。换不掉的那一处在文件头写明。
- 自证用 `--selftest`、同包里的测试，或红绿样本目录（每个样本带一份写明期望退出码与输出的文件；样本里要留的空目录放一个 `.keep`，git 存不下空目录，门禁阶段「脚本执行位」判）：每一种判定（绿、红、本次未跑、用法错）至少喂一个答案已知的输入，判出来与答案相同；入口脚本的列项、点名、拒绝认不得的项名、失败计数、项数核对各走一遍。
- 每一处会判红的分支，配一个弄坏开关或一条变异：弄坏之后自证要红，红在点名的那一项。弄坏开关在脚本文件头逐个列明：开关名、弄坏哪一处、打开后哪一项该红；变异进入库的变异清单（`show-me-test.md`「新增的测试必须先证明它会红」）。复跑的一方（自证自己，或门禁的自证）逐个打开、看它红在点名的那一项。开关只给自证用，平常跑时不认。
- 自证接进门禁或快档，改了测试脚本或判法就跑到。自证用假的驱动，不起编译与重活，改脚本的人随时能跑；项目拦重型测试的闸不拦自证。
- 自证同样守「用例原子化：每一条都能单独跑」。

## 分快慢两档

| 档 | 装什么 | 什么时候跑 |
|---|---|---|
| 快档 | 按项目定的快慢判据归为快的用例，加上一律进快档的那几类 | 每次改完 |
| 慢档 | 按快慢判据归为慢的用例：穷举、长时间随机、真设备、外部工具这类 | 跟着全量跑：提交前或用户要求时；别的时机由项目定 |

- 快慢判据与两档各自的命令写在项目本地规则里。判据可以是单项耗时的阈值（按平常跑时量到的数判），也可以按要不要穷举、要不要真设备或外部工具来分；拿不准的归慢档。
- 档位标在用例上或登记表里，不在脚本里另抄一份名单。
- 一律进快档、不看快慢判据的几类：慢档每一种判法的小输入用例（同判法、小输入）、剪枝自证、多线程与单线程的对拍、优化前后的对拍、加速路径与参照路径的对拍、从全量钉回来的红例。要特定硬件的那几条，在没有那种硬件的机器上报「本次未跑」。
- 用编译开关（特性、`cfg` 这类）分档的，快档里至少有一趟把它编进来；某一类编进来 0 条，报「本次未跑」，不算跑过。

## 判定可复用：按输入存，按前缀剪

- 每一份判定按它依赖的全部输入算键存下：被测代码、判法代码、参数、工具链。键相同的直接复用，不重算。
- 判定库不是这一趟的输出：输出照 `show-me-test.md`「门禁不许假装通过」每趟新写，复用来的判定在输出里与现判的分开报；判定库放哪照 `command-safety.md`「测试镜像一律放临时目录」里跨轮缓存那一句。
- 状态空间按共享前缀组织：几条流、几个项共有的前缀只判一次，后面的接着它判。
- 剪掉的只能是两种：键相同、已经判过的；与已判状态等价的。等价关系写成用例钉住。
- 按登记整批不判的一类不算剪枝：登记表一行一类、写明为什么不判，成功那句报跳过了多少，照 `show-me-test.md`「门禁不许假装通过」列出没判的是哪几类。
- 剪枝要自证：在小规模输入上关掉剪枝与复用跑一遍，判定与开着时逐项相同。剪枝自证进快档。
- 一块判完才落盘，写入是原子的；被打断后重跑同一条命令就是续跑，只补没判的。
- 成功那句报「现判 N、复用 M」。
- 整个脚本的输入没变就不重跑，写成 `admission: inputs-changed`（`preflight-discipline.md`）；判定一级的复用在脚本里做，两层都要。

## 编译与算法都要快

- 重型用例用优化构建跑，溢出检查与断言照开（Rust：`opt-level = 3` 加 `overflow-checks = true`，`assert!` 一律留着）。只在调试构建里生效的断言（`debug_assert!` 这类）开不开，由项目量过代价之后定，关掉的在构建配置旁写明量到的代价。
- 一趟只编译一次：几个项共用一份构建；构建产物跨轮复用（放哪照 `command-safety.md`「测试镜像一律放临时目录」里跨轮缓存那一句），跑之前不清掉。
- 热路径上不做与判定无关的事：格式化、逐条日志、反复分配。
- 进程内互相独立的单位按区间切片并行，并行度照 `command-safety.md`「一个脚本里的检测项，能并行就并行」。合并要确定：计数按片的次序相加，「第一处」取序号最小的；多线程与单线程的对拍逐字相同，进快档。不能并行的（共享状态、次序本身就是被测对象）在那条用例的注释里写明为什么。
- 单项跑得超过项目定的进度间隔的，每过一个间隔至少打一行进度：每片报区间与已判的数。
- 优化不许换掉判据：优化前后在同一组输入上判定逐项相同，这组对拍进快档。

## 用上现有的硬件加速

- 哪几类计算走加速硬件（GPU 这类）、用哪几台机器、各给多少额度，登记在项目的本地配置里；登记了的那几类只走加速路径，配置了几台机器就分到几台。
- 配置开了的硬件或机器是整个脚本离不开的，写成 `run-condition: check`：用不上（设备不在、驱动不对、内核编不过、显存不够、第二台连不上）就退 78，出路写「修好设备，或改配置」；不悄悄退回 CPU 或单机。要退回就改配置或显式传参。
- 加速路径留一份 CPU 参照实现，两边在同一组输入上判定逐项相同；这组对拍进快档。
- 加速路径同样先证明会红：往加速那一侧塞一个已知故障，对拍要红。

## 全量的红，钉回快档

- 全量每出一个红，把触发它的输入做成快档里的一条用例或登记表里的一行，在快档里复判；修好之后留作回归，不删。
- 钉之前能缩就把输入缩到仍然红的最小那一个；缩不了的写明为什么，原样钉。钉完核一次：在出红的那份代码上，钉住的用例同样红，红在同一条断言上。
- 项目有一张钉表，每钉一条登记一行：出红的那一行整行抄下、带产物文件名，以及改回哪一处（变异或那次提交）它就红。
- 全量产物里的每一个红，在钉表里都找得到对应的那一行，才算关掉。

## 门禁管哪一半

**还没有一条做成了共享检查。** 能按字面判的几样，项目可以在 `.claude/gate.d/` 里接本地阶段判：
入口脚本的参数约定（`--list-items` 退 0 且不起编译和重活、项名写错退 2）、自证（三种形态之一）在不在、跑了是不是绿、文件头列明的每个弄坏开关打开之后自证红在点名的那一项、全量产物里的红是不是都在钉表里、按参数循环的用例拆没拆开、一律进快档的那几类对拍在不在快档里。

靠 review 的：自证覆没覆盖全每一种判定、用例是不是真的互不依赖、复用的键罩没罩全输入、剪枝的等价关系对不对、快慢判据定得合不合理、热路径上有没有与判定无关的事、该走加速硬件的计算登记全没有、钉住的用例与全量的红是不是同一个缺陷。
