# 收尾：每轮工作结束前必做

## 0. 报进度——排在最前，不许省

一行三件事：**现在在哪个里程碑 / 门禁过不过 / 还缺什么证据**。
状态一律现查（跑一遍 `gate.sh`），不许从上一轮的笔记里抄。

**还要说清这一轮给这个数加了多少。** 经常是 0：出了个零结论、
推翻了一条决策，或者只是弄明白了某个证据现在还拿不到。**那就写 0。**
把别轮的成果算进这一轮，进度表就变成只涨不跌的东西，也就没用了。

## 1. 这轮敲的脚本/命令，有没有该收归 `scripts/` 的？

判据是「**会不会被抄第二遍**」，不是「写得好不好」。

**踩过的坑要做成会失败的检查，不要做成一句提醒。**
写一句「注意别在 X 的时候做 Y」拦不住手敲命令，
能拦住的是一个当场**拒绝执行**的检查。

反过来也看一眼：有没有已经没人用的，该删就删。

## 2. 这轮用到的 skill / 规则，有没有该改的？

看看有没有哪一步是靠记性撑住的、判据是不是事后才补的、同样的样板是不是又抄了第三遍。
**有就当场改那个文件**，别留到「下次」。

改哪里，看这条管的是什么：

- **管协作**（证据、文档、决策落点、门禁反馈）→ 改 singlefs-ai-sop，并抬 `VERSION`
  （改哪些路径要抬版本，见 `scripts/version-discipline.sh` 的 `GOVERNED`）
- **管文件系统怎么设计** → 改项目本地的 `kb/`、`.claude/rules/` 或项目 `CLAUDE.md`

**拿不准就放项目本地。** 这套 SOP 只有 singlefs 一个使用者，
「别的项目会不会也需要」不是判据——没有别的项目可看，那句话谁都能答「会」。

## 3. 决策有没有变动？

这一轮如果推翻或者定下了任何设计决策，**当场写进 `kb/decisions.md`**，带上依据。
决策记录漏一条，三个月后就得翻旧账才能回答「当初为什么这么定」。

**掂量完给个说法，也算一次决策变更。** 你说「这条现在不该定」「还是维持原方案」，
如果这实际上推翻了 `kb/decisions.md` 里已经写下的某句话，那就是一次推翻，
同样要当场记进去，带上依据。
说法只留在对话里而决策文件不动，三个月后没人知道那句话为什么不算数了。

## 4. 同一个仓里有没有别的会话在飞？

几个会话同时在一个仓里干活时，有四个平常成立的前提会失效。收尾前逐条对一遍：

- **「工作区里的都是我改的」不再成立。** 提交前把改动分成「这一轮的」和「不是这一轮的」，
  只提交这一轮的。把别人的半成品卷进提交，等于替他发布了没验完的东西。
- **「门禁红了就是我改坏了」不再成立。** 判红之前先看失败涉及的文件在不在这一轮的改动里。
  不在就如实说「红了，但不是这一轮的」，别顺手去修——那是别的会话还没收尾。
- **公共编号先到先得。** 历史条目序号、实验号这类大家共用的编号，取号之前先看已有的最大号。
  改公共文件只做定点替换，别整篇重写——重写会把别人刚写进去的东西悄悄抹掉。
- **「新建一个文件不会盖掉谁」不再成立。** 另一个会话可能几分钟前刚取了同一个号、写了同名的未提交文件，
  而整份写入的工具会静默覆盖它——没进过 git 的东西，盖了就找不回来。
  新建文件用排他方式（`set -o noclobber`、`open(路径, 'x')`），取号要在写第一个文件的同一条命令里现查；
  能在工具层拦（写入前的钩子拒绝覆盖未跟踪的文件）就在工具层拦。
  实测（2026-09-12）：一次整份写入盖掉了另一个会话刚写的跑前登记，靠那个会话的对话记录重放才逐字复原。

撞过的号，能做成会红的检查就做成检查（见 `rules/show-me-test.md` 的
「踩过的坑要做成会失败的检查」），项目侧照着历史文件的编号形态写就行。
