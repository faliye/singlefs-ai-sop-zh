# 测试纪律

## 单次观测不算数

跑至少 5 轮。要说「通过」就得每轮都通过，要说「失败」就得每轮都失败；
两边都不满足，就如实说「不稳定」，不下结论。

前提是观测本身有变化：真实 I/O、并发、时序、随机源，至少占一样。
一样都不占的是确定性模型，只能写成「跑 N 轮说明的是没有隐藏状态，不是统计上稳定」，
证据强度靠变异测试和钉死绝对值的断言，不靠轮数。

## 读不到 ≠ 读到 0

指标读出来是空的，要重试，而且**这一轮作废**，绝不能当成 0 拿去算。

## 分段计时在被测进程里计，不在转发输出的循环里计

包装程序起一个子进程、读它的输出行、逐行转打出去时，**不许拿每行读到的时刻当分段挂钟**。

**做法**：在被测进程里自己计时，把数写进结果行；非要按到达时刻切，先把子进程的输出整份读完再转打。
外层与里层两个数都有时，报一个包含自检：外层那一段必须包住里层那一段，包不住的轮不进统计。

## 实验开跑之前，答案不许已经存在

**不许预设结论，设计阶段也不许参考任何已有结论**：这个项目上一轮的结论、
别处的定论、自己的直觉，一概不看。

**该读的是定义，不是答案。** 被测对象的口径、参数、语义要逐字读
（见 `verify-before-claiming.md` 的「它定了没，和它到底怎么定义的，是两个问题」）；
「上一轮测出来是 X」「某某项目说这样更快」是答案，不读。

**做法**：判据、阈值、作废条款都在跑之前写死，写完再去看已有结论。
两边对不上就如实并列，不许回头改判据——**改了就是新实验，重跑。**

**阳性对照的答案，不能放在被测的那一方读得到的地方。**
被测的是一个会读仓的 agent 时，答案不写进它要跑的脚本、不写进同一个仓的记录；
只存哈希也不够：候选空间小、又不加盐的短哈希算明文。
当盲测用的答案不进被测方能读的仓，或者换一段它没见过的历史；留在仓里的对照只当回归检查（防工具被改窄），不当盲测。

## 实验的失败条款不许让结论不可证伪

**不许把「没测出效应」一律写成实现有 bug。** 两件事分开，**两个对照组都要跑**：

| 对照组 | 作用 | 测不出差异时怎么判 |
|---|---|---|
| **阳性对照**：效应在文献里确凿存在的那个基线 | 证明这套测量分得出差别 | **实现有问题，整轮作废** |
| **真实基线**：这个项目实际打算实现的那个方案 | 回答实验真正要问的问题 | **是个正当结果，如实记下来** |

**每写一条失败条款，紧接着写一句「什么观测会让它触发」。**
写不出那句观测，这条条款要么前件写反了、要么写空了，都按没有条款算。

### 判据不写成合取，门槛不能是臂定义的同义反复

- **不把两个量合成一个 true / false**：每个量各占一行、各报各的判定，合取留给人做。
- **门槛不能是被测臂的定义**：写门槛之前把被测臂的定义并排放一遍，门槛能从定义直接推出来的，那一格不算判据。

## 阳性对照必须对**每一条**被测的臂都跑

对照那段循环必须遍历所有臂，不许写成「拿第一条跑一下」。加臂时连对照那一段一起改。

## 只让多条臂互相比，测不出「所有臂一起错」

**每写一条互比断言，旁边就要有一条把绝对值钉死的断言。**
「三条臂的开销相等」不够，还得有「开销正好等于 N」，而 N 要另外算出来。

**做法**：写完一条互比断言就问自己一句「要是三条臂**一起**错了，谁会发现」。
答不上来就补一条钉绝对值的。

## 端点不是轨迹：被条款当谓词输入的量，实验要报轨迹

一个量被某条条款当停机 / 起跑 / 准入谓词的输入时，至少报三样：
**吃光初始供给之后的峰值、为正的轮数、期末值**；
只报期末值的，正文里不许写「从来」「恒」这类说轨迹的词。

## 实验要写清为哪个决定而量、量到哪算够

跑前登记只写「量什么」不够，还要写**这个量为哪个决定而量、它取什么值会让那个决定翻面、量到哪一步那个决定就能判**。
写不出这三样的量不登记。

- **选择与结论分开写。** 交选择的时候另写一份只有问题的清单：每个选择的候选、什么观测会让选择翻面、量到哪算够。
  它不带倾向、不带数，可以原样交给设计实验的一方。
- **登记里每个量对应清单的一行**，对不上任何一行的不登记。
- **每段交回附一张表**，逐行写「已够判 / 还差什么 / 剩下的量能不能让它翻面」；续派之前先点名还差的那几行，一行都不差就停。
- **「够判之后没跑」是合法结局，不是欠账**，实验状态里要写得出来。

## 变异测试证明的是断言会红，不是覆盖

变异只证明「凡是写了断言的代码都被变异测过」，**不证明**「结论涉及的每一处代码都测过」。

不许写「零盲区」，只能写「N 条变异全部被抓」。写完结论再回头问一句：
**这条结论的算术是从哪来的，那部分有断言盯着吗？**

两个坑会让变异悄悄失效：

1. **常量断言写加法，别写减法**：写 `assert_eq!(A, B + 240)`，不写 `assert_eq!(A - B, 240)`。
2. **等价变异不算盲区，但要分开记。** 在所有输入上都跟原式同值的变异，判定为等价的，
   把等价性写成一条测试留档，再换一个真会改行为的变异补上。

## 检查本身也可能是错的

下断言之前先确认这个检查**分得出差别**：验「没有非法块」的时候，
同时确认扫描真的读到了块。

写完一个检查就问：被测对象真坏了，它会不会红？答不上来就是还没写完。

## 门禁管哪一半

**测试纪律里做成了检查的只有一条**：改了 `crates/*/src/` 就得带测试，由 `scripts/show-me-test.sh` 判。
另有一项写在 `gate.sh` 每次都打印的未实现清单里：最终判据，由项目定（`show-me-test.md`），只能由项目在 `.claude/gate.d/` 里接上并声明 `# gate-covers:`。
项目自己的验证手段登记在项目根 `.claude/gate-not-implemented.tsv`（一行一条：键、缺的是什么、覆盖之后仍要提醒的话），`gate.sh` 把它们并进同一份清单，同样由项目在 `.claude/gate.d/` 里接上并声明。

**其余全靠人，而且暂时不打算做成检查**：轮数够不够、确定性实验怎么写、判据是不是跑前写死的、
两个对照组跑没跑、失败条款会不会触发、互比旁边有没有钉绝对值、被条款当谓词输入的量报没报轨迹、
变异是不是等价、检查分不分得出差别、阴性结果证没证明路径跑过、
分段计时是不是在被测进程里计的、阳性对照的答案被测的一方读不读得到、登记的每个量对不对得上一个要判的决定。

## 阴性结果要能和「代码没跑到」分开

「没复现」不等于「没问题」。想说「这条路径是对的」，
得拿出读数证明那条路径**真的跑过**。
