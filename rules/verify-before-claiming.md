# 陈述外部状态之前，现查一次

**凡是说「外面现在是什么样」的话，出口之前当场跑一条命令确认。**
记忆、kb、上一轮对话、TODO 表，都只是线索，不是证据。

「外面」指的是：不在这次对话里、而且可能在我不知道的时候被改过的一切。

| 要说的话 | 现查的命令 |
|---|---|
| 门禁现在过不过 | 引最近一次 `gate.sh --staged` 的汇总（带日期与那棵树的哈希）；那之后有改动就不说「过」，说「上次绿、之后改了哪些没跑」。门禁只在提交时跑，不为说这一句重跑 |
| 某个不变量实现了没 | 读 `kb/invariants.md` 的状态列，再 grep 实现它的检查的源码，确认它真的在 |
| 某个决策定了没 | 读 `kb/decisions.md`，看状态是「已定 / 半定 / 待定」哪一个 |
| 工具链 / 环境齐不齐 | 跑 `scripts/env.sh` |
| 别家实现怎么做的 | 现查它的文档或源码，并在 kb 里标上来源和「未在本项目验证」 |
| 被测对象或它的产物现在什么状态 | 现场跑项目的检查，不要靠「上次跑过是好的」 |

**不用现查的**：这次对话里刚读过的文件、纯代码逻辑推导、算术。

## 它定了没，和它到底怎么定义的，是两个问题

查了状态列、确认某条决策是「已定」，**不等于你知道它定的是什么**。
拿一条决策去做任何推导（建模、写检查、推翻别的结论）之前，先把它的定义句原样贴进你的笔记或实验注释。
贴不出来，就别拿它推导。

## 核了窄的那一句，说出口的却是宽的那一句

⇒ **判据：说出口的那句话，它的主语和范围，是不是就是你刚才核的那一个？**

- 核的是「这条路不通」⇒ 只能说「这条路不通」，**不能说「做不到」**。
- 核的是「这个文件里没写」⇒ 只能说「这个文件里没写」，**不能说「全仓没有」**。

⇒ **做法**：把要说的那句宽的话当成待证命题，问一句
「**要让它为真，需要排除掉哪些情况**」，然后逐个去排除。
排不完就把话缩回你真排完的那个范围。

⚠️ 判「一个对象有没有被条款罩着」之前，**拿它的名字全仓搜一遍**，
看它有没有被归进某个已有的类。

⚠️ **截断过的输出也是「窄的那一句」**：`grep … | head -12` 看到的是前 12 行，不是全部命中。
⇒ **要说「只有这几处」「命中的就是这些」，输出不许截断**；嫌长就先数（`grep -c`、`| wc -l`），数对上了再看内容。

## 拿来下结论的命令不丢输出

要据一条命令说「零命中」「没出错」「退出码说明了什么」的，这条命令不把 stderr 丢进 `/dev/null`，也不丢 stdout（`2>/dev/null`、`&>/dev/null`、`>/dev/null 2>&1` 都算丢）。
`grep -c 模式 文件 2>/dev/null || echo 0` 这一类写法打出的 0 不当零命中。

空输出、0 先确认命令真跑成了：看它的退出码（同一条命令末尾接 `; echo rc=$?`）与报错，跑成了再当零命中。

## 检查还没出结局，不写成过了

交出去、还没跑完的检查（测试、门禁、复跑、自证），正文、记录与报告里只写「交了、等结局」，不写「绿」「过」「全抓」。
结局出来、读过判定的那一行，再改成结论，并引那一行。
几件检查写在同一句里的，没出结局的那一件单独拆出去写，不跟着已经过了的那几件一起写成过了。
被取消、撞了资源上限或被打断的那一次运行，日志里已经打出来的 ✓ 不算结局；结局以调度它的那一方给出的最终判定为准，引的时候引那一行。

## 转述别处的做法，带出处或原文

派给子 agent 的提示、发给别的会话的消息里，说「与 X 同口径」「照 X 那一份」「同 `X`」的那一句，同一句里要带下面三样之一：

- `路径:行号`（或路径、「同文件」加「第 N 行」）；
- 原文引用：「」里至少 6 个字，或者以冒号收尾、下一行是 `>` 起头的引用行；
- 路径加反引号里的函数名，或「」里的标题。

拿不准原文是什么，先读一遍再派。只写出你理解的内容（「同一口径：取限定名」）不算出处。

## 门禁管哪一半

钩子 `scripts/claude-hooks/borrowed-convention-guard.sh`（判定在 `scripts/borrowed-convention.py`）管「转述别处的做法，带出处或原文」：派子 agent（Agent、Task）与 SendMessage 之前判，借用句同一句里没有出处或原文就拒绝。
它认的借用说法以 `scripts/borrowed-convention.py` 的 `BORROW_PHRASES` 为准，不在里面的说法不判；出处指得对不对、原文抄得对不对，它不判。
项目在 `.claude/settings.json` 上注册它，写法在那个钩子的文件头。

钩子 `scripts/claude-hooks/discarded-output-count-check.sh` 管「拿来下结论的命令不丢输出」的一半：Bash 命令跑完之后判，命令里丢了输出、同一条命令又在判计数或空（`grep -c`、`wc -l`、`test -z`、`[ -z`、`|| echo 0` 这类），记进检出记录并提醒一句，不拒绝。
它认的写法以那个钩子的 `DISCARD_FORMS`、`COUNT_FORMS` 为准；命令里写了 `# discarded-output: <为什么可以丢>` 的只记不提醒。据那条命令下没下结论，它不判。
项目可以不注册它（文件头写了 `# hook-registration: optional`），注册的写法在那个钩子的文件头。

其余各条没有做成检查。`scripts/doc-lint.sh` 只查得了写下来的那一面（kb 的出处与状态、编号带不带简称），
查不出「这句话是不是刚核过的」。「说出口之前现查一次」全靠人
（`show-me-test.md`：门禁证明的是证据要求被满足，不是语义正确）。

## 落实

- **要改 kb 或 TODO 里任何一行状态，先跑那一行对应的命令。** 不查就别重写它。
- 说不出「我是靠哪条命令知道的」，那句话就写成**推测**，不能写成事实。
- 别人提出的事实性更正**同样要核**。不照单全收，也不急着反驳，核完把结果说清楚。
